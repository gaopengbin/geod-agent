# GeoD Earth History 0.1.0

独立的 Google Earth 历史地图影像适配器，用于 GeoD Agent 原有的本机影像任务。输出类型是 `processed_map_imagery`；历史目录日期与实际拍摄日期分别保留。

协议解析、缓存和投影采样源自旧 GeoD 的 Keyhole 实现。`UPSTREAM.json` 记录原仓库、当时的 HEAD、未提交源码的逐文件摘要和本仓库副本摘要。副本已纳入本仓库，不依赖旧 GeoD 安装、旧仓库目录、符号链接或外部 `file:` 包。保留原 GeoD 项目的 MIT 许可与贡献者来源。

## 流程与边界

1. `initialize` 指定当前桌面配置的历史记录目录。
2. `discover` 从 Google 的历史目录查询一个位置在指定级别的真实日期，并返回 `catalogId`。点位目录不等于整个下载区域的覆盖证明。
3. `select_snapshot` 固定该目录根和用户截止日期，生成内容绑定的本机 URI。图源显示名称和登记 ID 可以独立命名，URI 中的快照不能改写。
4. 下载每张 XYZ 瓦片前固定其原生块选择；重启、暂停和恢复复用这些选择和原有验证缓存。按截止日期或之前选择版本，不替换为实时瓦片。
5. `tile_evidence` 生成逐块日期、版本、提供方、原始响应摘要和未知拍摄日期说明。桌面导出时将其写入有摘要校验的元数据资产。

原生块重采样为 EPSG:3857 的 256 像素 XYZ 瓦片，再由已有导出管线裁剪与生成成果。输出网格级别不代表每块影像都有相同原始分辨率。某张输出瓦片的原生覆盖不完整时按缺失处理，不能用透明图块表示完整成功。

本机 URI 只能引用真实已保存的快照，不能成为模型指定任意网络目标的入口。网络请求固定在 Google 的 HTTPS 历史服务，不跟随重定向，不接受用户 Cookie 或模型填写的认证信息。目录与原始块缓存校验 SHA-256；原生编码参数不进入模型回复。

日期含义参照 [Google Earth 图像日期说明](https://support.google.com/earth/answer/6327779?hl=en)：历史时间轴表示指定日期或之前的影像，组合影像可能涉及多个拍摄日期。本接口不把目录日期当作逐像素拍摄证明。

## 开发验证

`examples/probe.rs` 是开发验收入口，可查询真实目录并读取一个历史块。桌面产品通过 Source Creator 的 `google_history_dates` / `google_history_source` 接入正常图源登记、确认、下载和核验；探测程序不是新的公开 CLI 产品。

单位测试覆盖日期选择、持久快照校验、URL 边界、原生坐标和采样、空数据、损坏选择以及有界解码。完整桌面实跑与成果证据见 `docs/implementation/2026-10-27-google-earth-history.md`。
