# 精简问候保留 GeoD Agent 产品定位

## 问题

用户的真实截图中，单句“你好”被回复为工作区项目助手，并主动列出代码分析、脚本执行和本机路径。精简输入分支只保留了产品名称，丢失地理数据产品的定位；仍保留的原生环境信息因而容易被当成用户的任务。

## 修复

- 在模型输入投影中加入共用的简短产品定位，问候与正常任务都保留：GeoD 产品体系中的地理数据桌面 AI 助手，核心工作流是描述需求、按实际权限确认具体计划、获取和查看本地成果。
- 产品能力围绕影像下载、图源、范围与 GIS 数据、二维/三维地图、定时任务、已启用的 Skills/MCP 描述。代码和脚本在用户提出相应任务时介绍和使用。
- 明确工作区目录仅为原生文件系统上下文，不代表用户已要求处理该项目；问候不主动输出路径。
- 问候使用一到两句简短欢迎与地理数据需求引导。原生环境、权限、任务历史、按需工具加载和持久化 Core 线程保持原有机制。

## 验证

- 45 项测试通过，零跳过；新增中英文问候及正常自我介绍的产品定位检查，并在真实打包 Core 请求中验证定位确实发送。
- 真实 Core 的模拟 Responses 问候从 89,685 bytes / 82 工具降至 7,907 bytes / 0 工具，仍减少约 91.2% 的请求体积。此处不把字节数当作 token 回执。
- 原生开发版重新编译、空闲检查、正常退出并重启，新二进制 SHA-256：`8eadd0f5d9e2e8cec6d6f9dc5ab11c140b2fa1197472b6ca92d9f857a279def2`。
- 完整原生调用链确认：本地供应商收到共用产品定位、简短问候约束和零工具，问候请求 3,984 bytes；同一 Core 线程可发现准确工具 schema 并读取真实图源。
- 验证使用本地模拟供应商，没有调用托管模型。检查的是规则进入实际模型请求与正常任务链路，不把模拟回复当作真实模型的语义质量验收。
- 重启前后现有聊天、地图命令、任务、默认模型和余额一致。用户正常使用后的余额为 466.66352 Credits，测试前后没有变化。

证据：`artifacts/greeting-identity-20261010/native/acceptance.json`、`before.json`、`after-restart.json`；原生检查工具为 `scripts/verify-model-input-native.mjs`。
