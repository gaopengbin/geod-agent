# 启动首屏与空会话工作区误报

## 原因

- 原生窗口先显示，初始 HTML 的 root 为空；React、地图模块和本地历史记录加载完成后才挂载开屏，因此前面有一段空窗口。
- 工作区初始化不论是否有历史任务都调用 `imagery_plans_claim`。首次空会话还没有保存本地工作区绑定，因而被误判为需要恢复旧任务的工作区。

## 修改

- 初始 HTML 提供完整本地品牌开屏，共用 React 开屏的标志、球体与文字，轻量脚本在主模块之前执行。
- 主窗口先隐藏，收到首屏就绪信号后显示。页面加载完成事件兜底，隐藏 WebView 不触发动画帧时也能就绪。
- 从首屏就绪计时，主界面加载完成后只补足原定约 2 秒时长；加载慢时保持开屏。记录恢复错误页能主动解除开屏遮挡。
- 新会话没有计划时前端不调用迁移；原生空迁移请求返回空结果。真实历史计划仍保留原来的账号、会话与工作区校验。

## 本地证据

- 前端构建通过，保留现有地图大包提示。
- 7 项启动脚本与本地记录测试通过，覆盖隐藏窗口动画帧停滞、只显示一次、旧原生兼容、减少动态效果以及记录恢复错误。
- 原生首屏显示门控单元测试通过。
- 浏览器中阻断主模块后，真实初始 HTML 开屏持续显示；恢复模块后正常进入应用，无重复开屏。截图在 `artifacts/startup-20261014/`。
- 更新的原生启动预览以独立配置目录运行，启动记录为 `native-preview-r2.json`。原开发窗口和后台进程保留，本轮没有模型调用。

浏览器截图与原生启动记录分别证明首屏内容和启动结果；未将其当作原生冷启动全程录像或线上正式包验收。
