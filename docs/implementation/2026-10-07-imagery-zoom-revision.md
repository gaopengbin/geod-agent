# 修改影像层级时沿用任务坐标系

## 实际故障

用户在已生成的 route_1km_buffer 计划后发送“改成z14”。原计划为 Esri World Imagery、z18、GeoTIFF、EPSG:4326、未压缩、无金字塔。模型实际 plan_imagery 参数也已携带 EPSG:4326，仅 zoom 改成 14。

应用的成果坐标系校验只检查最新用户消息、与该消息绑定的问答或会话默认，没有区分修改已有任务与创建新任务。所以即使模型已经正确传参，仍弹出了两页坐标系/应用范围卡。单独相信模型传入 targetCrs 不能解决问题：新任务仍需真实用户意图。

## 修改

- `imagery-revision.ts` 识别明确的单一层级调整，例如“改成z14”“层级改为14”“change zoom to 14”，也处理该修改的显式继续指令。模糊数字、其他新任务、另改投影或源坐标系文字不作为继承授权。
- 查询同一会话实际创建的、由当前账号持有的原生计划。核对原规划记录、图源、输出格式、范围和本次指定层级；读取该计划真实 CRS/重采样参数。模型文字、模型自己填的 targetCrs、无关或不存在的计划不能满足校验。
- 本机 plan_imagery 校验使用上述任务选择，并在计划参数中填写实际 CRS，不写入会话默认，也不放宽下载审批。
- 对已经弹出的、应用自动生成的重复卡，保留原始问答和草稿，记录 existingPlanCrs 来源与真实 planId；显示“已沿用原任务坐标系”。不同 CRS 草稿、自定义草稿、范围草稿或已提交答案不会被替换。
- 已经被旧实现卡住的等待轮次结束，不伪造新回答、不新增收费模型请求。只有对应原生回执已结束、该代模型回执已 settled 时，才解除残留待核对状态。用户可点“继续调整计划”，后续生成新计划，下载仍通过原审批流程。
- 中英文提示沿用现有问答组件、按钮和字体；保留错误反馈，历史其他任务的继续入口不可误续当前请求。

## 验证

1. 16 项相关回归通过：明确/模糊层级表达，实际原生计划继承，继续同一修改，图源/范围/格式不匹配，新任务及不明确投影仍询问，缺失/非本会话计划拒绝，问答/草稿持久化，以及已有 MCP 问答恢复逻辑。
2. 前端类型检查与生产构建通过，保留既有大分块提示。
3. 当前真实桌面和原会话验证：读取实际原计划 EPSG:4326，重复卡持久化为来源记录，原消息与工具记录校验不变，原计划 hash/计划列表不变，用户匹配原 CRS 的草稿保留，会话默认仍为空。旧等待轮次 interrupted，原生生成数仍为 1，未新增模型调用或下载。继续按钮可用，输入框恢复，刷新后状态保留。

证据位于 `artifacts/imagery-revision-20261007/native-report.json`、`native-inherited-crs.png`。

## 范围

这次覆盖单个影像计划的明确层级调整，不把某次任务坐标系推广到整个会话，不将其他类型或批量任务猜成同一任务。实际 z14 新计划和下载尚未自动重新执行。本机开发版已更新，未发布安装包或线上服务。
