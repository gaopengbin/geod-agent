# 影像处理阶段与磁盘预算显示修复

## 实际问题

昌平区 Z14 作业的本机记录显示：下载开始 14:33:39 UTC，704 张瓦片于 14:33:57 全部下载，直到 14:36:49 才切到核验，14:36:51 完成。中间约 172 秒正在拼接、按行政边界裁剪、压缩和保存成果，但账本一直是 `downloading`。`artifacts/slim-skills-20261006/changping-status-before.json` 保存脱敏时间与文件大小证据。

该计划的磁盘预留为 962,592,768 字节；旧显示按二进制除数得到 918，却标注 MB。实际成果资产合计 158,897,883 字节，主 GeoTIFF 为 156,030,759 字节。空间预留是成果、下载缓存和临时文件的保守预检预算，不是压缩后文件大小预测。

## 改动

- 核心下载器增加真实阶段回调，在逐缩放级别下载前报告下载阶段，开始流式拼接、边界掩膜和输出时报告处理阶段。既有仅瓦片进度的回调保持兼容。
- 本机账本进入 `processing`，生成完成后才进入 `verifying` 和最终状态；多级别任务可在实际处理与下一组下载之间切换。
- 任务详情、列表和对话后台任务统一显示“生成成果”。下载条明确表示瓦片进度，处理阶段显示拼接、裁剪和保存提示。
- 处理阶段支持暂停、取消，保留已验收缓存；进程退出后可以恢复处理，包括 Agent 工具和定时任务的恢复路径。
- 待执行和运行时显示“建议空闲空间”及解释；完成后显示已核验成果资产的真实字节合计，原预留预算保留在参数详情。此面板大小使用十进制 MB/GB，避免单位歧义。
