# 待确认计划启动与错误反馈修复

## 本次故障

本机 SQLite 只读核对确认：驻马店计划创建于 2026-10-01 11:32:34（北京时间），到期时间为 12:02:34；另外两个待确认计划也已过期，且三个计划均没有作业。原生审批拒绝过期计划，批量控制器把 IPC 的 `{code, message}` 对象直接 `String()` 转换，丢掉原因，显示成 `[object Object]`。App 和卡片各渲染了一次同一错误。

## 修复

- 新增原生 `revalidate_plan`：在逐次确认审批和完全访问启动前，根据当前已配置图源重新核算未启动计划。哈希一致且仅时间过期时更新有效期，保留原计划 ID、哈希、创建时间、范围、几何与输出位置。
- 当前图源或计划内容变化时返回具体错误，保持原计划不变。已有作业的计划不能通过此路径改写；恢复下载继续使用原有作业流程。
- 保留原有审批和启动的有效期、哈希及审批记录检查。重新核算成功后仍走真实审批和作业入队。
- 成功启动后重新读取计划，右侧详情同步原生核算结果。
- 提取统一 IPC 错误解析，兼容普通 Error、原生对象、嵌套和 JSON 字符串，防止对象字符串化。批量失败按行政区或数据名称标记。
- 右侧任务面板统一显示任务错误；单任务和批量控件交由面板展示，消除重复。错误后仍可重试或丢弃，下一次操作清除旧错误。

## 验证

- 前端构建成功；25 项错误、批量任务、计划归属、状态摘要和启动测试通过。
- 原生库及开发版可执行文件构建成功；12 项 SQLite ledger 测试通过，包括过期计划就地核算、审批入队、重启读取、配置变化拒绝、已有作业不可改写。
- 将用户本机数据库备份到临时目录，单独执行 `pending-snapshot` 诊断测试：原来 450、126、1295 瓦片的三个过期计划均保持原 ID/哈希/几何/输出位置，重新核算后可审批并入队。只修改临时副本，没有启动 HTTP 下载 worker。
- 独立浏览器 fixture 使用实际任务面板组件和原生形状的失败对象：只有 1 个 alert，没有 `[object Object]`，操作卡片内没有重复错误。模拟重试成功后 0 个 alert，任务进入排队，其他计划仍待确认。浏览器 warn/error 为 0。
- 在本机记录的 5 个作业都已完成后，仅重启 GeoD 开发进程加载原生校验；新可执行进程及 9233 的 GeoD Agent 调试端点已确认。Vite 继续使用 1420 热更新。

本次没有生成安装包或修改服务器。实际新下载由用户重新点击确认后执行。
