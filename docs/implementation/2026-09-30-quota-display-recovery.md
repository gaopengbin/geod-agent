# 模型额度显示和拒绝恢复（2026-09-30）

## 已核实原因

用户截图显示可用 22,579 / 200,000，但最后一个成功请求用了输入 9,429、输出 199，共 9,628。只读核对网关账本：已用 187,049，实际可用 12,951；不存在未结算或冻结中的请求。当前网关每次先预留 20,000，因此下一轮被拒绝，尚未调用上游模型。

客户端原来只在整个多轮流程完成后刷新用量。若后续请求失败，刷新被跳过；同时将明确的额度拒绝当成未知结果保留 pending，造成旧余额、恢复提示和输入锁定同时出现。

## 本机修复

- 普通和流式网关调用将 HTTP 429 + QUOTA_EXCEEDED 识别为独立错误；从响应读取实际剩余额度，以 K 显示，说明请求未提交。
- 额度拒绝保存已取得的工具上下文并清除该未提交请求的等待记录；网络中断或上游结果未知继续保留恢复记录，避免重复执行。
- 每个成功模型轮次、失败处理、打开账号面板时刷新用量；打开期间每 15 秒只读刷新。
- 账号面板分开显示可用、总额、已用及预留额度。原有保存的等待记录可通过“检查状态”核对；若重试被额度拒绝，按新规则结束等待。
- 服务器额度、预留规则及用量记录未修改；未进行额外付费模型验收。

- 原生回归覆盖普通/流式额度错误，验证 12,951 显示为 12.95K，并确保未知上游错误不被当作额度拒绝。
- 现有前端 26 项测试、TypeScript 和生产前端构建通过。
