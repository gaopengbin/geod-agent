# GeoD Agent 通用执行规则实装

日期：2026-10-10。状态：本地代码、真实 Codex 回放、开发构建和已重启开发版的原生验收；未发布安装包或线上服务。

## 架构

保留配套 Codex 0.159.2 的模型循环、线程恢复、工具路由、权限和上下文压缩。新增独立的 `RuntimePolicy`，在模型传输和工具执行边界落实规则；GeoD 的工具用途、错误分类和验收条件由版本化适配器提供。

调用链：

```text
用户输入 / 纠正
  → 原生账号与会话租约
  → Codex 线程、模型请求
  → 当前原生事实 + 持久检查点
  → 参数 / 能力 / 修订 / 恢复条件 / 操作回执检查
  → 现有原生工具执行器及审批
  → 分类结果、保存回执、记录证据
  → Codex 决策下一步或给出最终回复
```

动态 GeoD 工具通过主机统一分发。Codex 自身的命令、文件修改和 MCP 调用通过已审阅的 `PreToolUse` / `PostToolUse` 生命周期接入；终结条目补充记录失败操作，因为失败工具不一定触发 PostToolUse。命令在配套引擎的 Hook 输入中使用 `Bash` 名称，不能只匹配模型看到的 `exec_command`。这已通过真实引擎验证；协议参考 [OpenAI 源码](https://github.com/openai/codex/blob/main/codex-rs/hooks/src/events/pre_tool_use.rs)。

## 实际执行的规则

| 规则 | 运行层实现 |
| --- | --- |
| 目标和修订 | 每个检查点保存目标、最新用户输入、交付物、需求来源和修订号；`runtime_task_update` 比较当前修订。模型提出的目标不授予原生权限。 |
| 唯一执行权 | 延用原生会话租约和账号隔离；每次派发重新检查取消、身份、工作区权限和当前任务事实。运行中修改工作区权限后，旧 Core 权限不能继续执行工具，下一轮重新配置其权限。 |
| 参数继承 | 保存用户实际回答的稳定问题 ID、问题契约、值、来源和作用域；兼容回答直接复用。局部修改保留其他要求；失效字段须明确移除。坐标系默认来自原生用户选择。 |
| 能力契约 | 动态工具执行前验证 JSON Schema；MCP 必须先取得当前工具契约，再校验其嵌套参数。不支持的约束明确返回能力错误，禁止忽略约束直接执行。恢复线程明确传入最新 dynamicTools，历史调用仍保留。配置或模型契约变化使已缓存发现结果失效。 |
| 错误恢复 | 分类为暂时故障、参数、权限、认证、能力、结果未知、业务拒绝和内部故障。只对声明为读取的操作有限退避；遵守返回的等待时间。副作用不会自动重试。 |
| 重复与策略复盘 | 根据用途、对象、失败类别和原生条件归类，改变查询文字不能绕过服务冷却或权限条件。重复已知故障触发现有原生复盘卡，模型请求在调用供应商前等待决定。正常后台等待排除在失败重复检测外。 |
| 长任务和费用 | 沿用可选的会话累计费用政策、实际结算和未知费用核对；没有默认 12 次或单轮费用截断。继续原任务不重置费用。后台作业仍由原生服务承接。 |
| 操作幂等和恢复 | GeoD 已声明的副作用绑定目标、参数版本和稳定操作标识；重复提交读取已有回执。待提交先持久记录，失联后标记结果未知，先核对再重试。原生下载记录可自动核对不确定的启动结果，批量其他条目可继续。 |
| 数据和上下文 | 完整副作用结果保存在账号、会话隔离的主机目录；检查点只含摘要和引用，证据支持分页。每次模型请求重新注入检查点。沿用已有几何数据落盘、MCP 分页、RTK 输出精简；宽泛发现仅返回前 6 个完整工具 Schema，按确切名称补取完整 Schema。 |
| 验收 | 最终模型回复和业务完成分别记录。声明的全部作业/成果 ID 必须有可信完成证据；原生 completed 账本或实际文件核验可提供证据，partial 不能通过。通过验收后阻止当前目标的额外工具检查；新工作须建立新目标。 |

## 持久记录

记录位于既有账号、线程隔离的 Codex 主机目录，不写钱包或用户工作区：

- `execution-checkpoint.json`：目标、修订、确认参数、操作、恢复条件、证据与计数；临时文件写入并同步后替换。
- `execution-decisions.jsonl`：追加的派发、拦截、复用、纠正、复盘与结束记录；包含关联标识，不记录完整工具参数。
- `execution-results/<内容标识>.json`：完整操作结果；模型常驻上下文只保留有界摘要。

会话历史和原生下载账本继续使用现有存储。原生服务提供的权限、账号、连接配置修订和任务状态优先于旧模型总结。模型不能调用状态工具替换这些原生事实。

## 行为边界

- 目标相关性、用户是否在闲聊、探索是否有必要，仍需要语义判断。本版记录目标与证据，未采用关键词规则强制中断这些判断，也未宣称消除了所有模型弯路。
- 复用确认回答需要稳定问题 ID 与兼容契约；重新措辞造成不同契约时，不假装它必然是同一个问题。已有坐标系复用机制继续生效。
- 外部 MCP 未声明读取或幂等特征时按不透明操作处理：不自动重试，也不把一次返回缓存成永久状态。Codex 的任意命令同样不能靠文本判断其副作用；失联且无回执时保留未知状态。
- 参数校验支持当前原生工具使用的词汇，以及常见对象、数组、组合和本地引用约束；它不是完整的通用 JSON Schema 实现。未实现的验证关键字在派发前返回 `TOOL_SCHEMA_UNSUPPORTED`，需补充适配或换用可验证的工具。格式元数据按注解处理。
- 检查点不保证不支持幂等或状态查询的外部服务恰好执行一次。GeoD 作业可按原生账本核对，其他未知外部操作需要实际服务回执或人工核对。
- 验收适配器已覆盖原生影像/数据成果。任意网页发布、地图配置和开放探索需要各自的可信验收适配器；模型的成功文字不会自动变成通过验收的证据。
- 后台等待不会被判成失败重复。原生后台面板和事件继续负责进度；本次没有引入统一任务轮数上限。

## 验证

`test/runtime-policy.test.mjs` 使用脱离钱包的确定性执行器，以及实际配套 Codex 与本地假供应商。验证行为边界和环境结果，不要求模型遵循某一固定工具序列。

覆盖：参数拒绝发生在执行前、不同搜索词共享服务故障、有限重试与冷却、权限变化后恢复、重复操作复用、提交失联和重启、确认参数继承与失效、MCP 当前 Schema、正常等待与超过 12 步、取消、用户纠正后的旧调用失效、完整结果落盘、批量独立恢复、直接工具与原生 MCP 别名共用操作身份、全部交付物验收、部分结果拒绝、复用原生完成证据避免重复核验。

真实 Codex 回放另外确认：旧线程刷新工具契约并保留历史调用；动态副作用实际只派发一次；命令的原生前置检查失败时不会写入文件；文件操作通过 Hook 或终结条目回执关闭检查点；等待用户期间不会额外产生模型请求。

## 代码入口
