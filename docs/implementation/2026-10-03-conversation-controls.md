# 会话分支与消息队列本地验收

## 已完成

- 会话标题右侧增加分支入口。通过已固定版本的 Codex app-server `thread/fork` 创建新的原生线程，保留分支时的上下文，后续消息分别保存。
- 附件复制为新会话所属的图片，并校验内容摘要。分支不会获得原会话的任务审批或可执行计划。
- Codex 正在回复时，默认将新消息加入队列；也可以切换为补充当前回复。
- 队列显示为输入框上方的紧凑列表，支持暂停、移除和继续发送。队列按账号和会话保存，任务或回复完成后不丢失。
- 失败、停止回复以及需要确认恢复的会话暂停自动发送，避免在上下文尚未恢复时继续执行。

## 实际验收

证据：`artifacts/conversation-controls-20261003/acceptance.json`，3 项通过。

1. 实际桌面上传测试图片，真实模型保存随机状态码；点击分支入口，核对两个不同的 Codex 原生线程 ID 和分别归属的图片 ID。旧图片 ID 在新会话读取被拒绝，新图片可预览且摘要相同。
2. 原会话更新状态码，分支仍由真实模型回答旧状态码；原会话继续回答新状态码。
3. 真实模型运行等待命令，执行记录包含成功的 `commandExecution` 和 `QUEUE_READY`。执行中加入两条消息，移除一条并暂停；命令完成后剩余消息没有发送且仍保存在队列。继续发送后，真实模型回答剩余消息，被移除的消息没有进入对话。

详细记录为 `actual-parent-conversation.json`、`actual-branch-conversation.json`，真实桌面截图为 `paused-queue.png`。验收脚本 `scripts/accept-conversation-controls.mjs` 不使用固定模型回复。

## 范围

这次实现最新完成回复处的分支，不支持任意历史消息位置的分支。独立后台命令管理、队列跨异常退出的进一步恢复验收和多会话并行生成仍在功能清单中；没有把消息排队视为这些功能已完成。
