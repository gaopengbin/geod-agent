# 持续执行与会话预算

本次修改替代 `2026-10-10-model-cost-audit.md` 中临时加入的默认 12 次硬截断。用户要求长任务在有进展时持续执行，并指出费用不能按单轮消息重置。

## 当前规则

- Codex 原生执行不再设置默认模型请求次数上限，也不设置默认费用上限。旧账号配置中的 `maxModelRequests` 字段兼容读取，但不再执行或写回。
- 用户可以给当前会话设置可选累计 Credits 预算。上下文 Token 设置仍按账号共享；费用预算仅作用于当前账号、当前会话。新消息、继续执行和应用重启均不重置累计值。
- 本机 SQLite 记录原生派发的 generation ID。只使用托管服务返回的 `billing.chargeNanoCny` 实际结算值；重复回执不重复累计。自有/赞助渠道只记录请求，不编造供应方费用或消耗 GeoD Credits。
- 费用未知仍标记待核对。设置了预算时，新增未核对请求会暂停；按具体 generation ID 确认风险，不能用未知请求数量相同来绕过检查。确认卡提供原请求费用核对入口，查询原 generation，不重新生成。
- 达到预算后，下一次模型请求保持在原位置，等待明确追加预算或停止。追加额度按当前总预算和实际累计费用的较大值计算，并记录确认凭据；相同确认的重试不会再次追加。
- 动态工具、本地命令、文件变更、MCP 工具的实际完成结果进入重复检查。首次操作建立基线，随后连续三次已知操作的参数和结果均不变时暂停。A/B 循环也可识别；新参数、新结果、真实下载进度变化会清零。时间戳、耗时、JSON 键顺序不构成进展。
- 确认后继续相同 Codex 进程、会话、轮次和待发模型请求，不重新执行已完成步骤。模型请求等待计时可暂停，SSE 和宿主心跳保持连接。停止仍走真实原生中断并释放会话占用，成果下载服务独立保留。

## 设置与范围

“模型与渠道”使用当前会话 ID；输入栏上下文设置也可修改同一预算。输入栏显示已经记录的会话费用，弹窗区分上下文容量、费用预算和待核对请求。费用按每次请求结算后检查，最后一次请求可能超过预算；这是可继续确认的费用检查点，不是服务器的精确预付费封顶。账户可用余额限制继续由现有服务执行。

该本机费用记录从启用此功能后开始，不冒充此前完整账单；既有历史账单仍在余额与订阅中查看。重复检查识别确定的工具参数和结果重复，不声称能自动判断所有业务上的无效探索。后台和隔离任务遇到预算/重复检查时返回人工处理原因，不能无人值守自动批准。兼容旧历史错误展示，但停止使用 `MODEL_CALL_LIMIT` 来结束新 Codex 请求。旧版 legacy 对话不由此 Codex 原生控制器执行。

## 验证

- Rust：会话/账号隔离、35 次模型费用累计、重启持久化、重复回执、未知费用、后续费用核对、真实进度、A/B 重复、MCP JSON 文本、相同确认重试、追加费用原子事务。
- 真实捆绑 Codex 引擎 + 不扣费的模型结果：同一轮 16 次模型请求、15 次工具执行；在第 14 次请求暂停，等待超过测试缩短后的请求超时仍不退出，继续原进程/轮次完成；等待时停止能够实际中断。另有既有用户等待/IPC 中断测试。
- 设置与执行确认卡：浅色/深色、380px 窄屏、会话/账号隔离、保存/恢复、预算验证、继续/停止、响应错误后保留确认卡并允许重试。浏览器固定数据验证不代表已消耗真实托管模型额度。
