# GeoD Agent 真实会话执行复盘

审查日期：2026-10-10。范围为本机保存的真实会话和当前工作区代码；本次只做审查和取证，没有发起新的托管模型请求、下载实验或线上修改。

## 结论

GeoD 高频业务需要由应用维护明确的任务状态、数据引用和工具能力。当前让模型自行拼接通用工具，容易把“有新工具输出”当成“任务有进展”，并在业务工具缺失时退回命令行探索。费用预算和完全相同调用的重复检查已有作用，但不能单独解决这些业务错误。

建议先补齐三条可直接执行的业务链：

1. 已配置图源 → 当前 2D/3D 视图切换底图 → 返回实际加载结果。
2. 路线结果引用 → 距离缓冲区 → 保存裁剪范围 → 影像计划。
3. 范围 + 历史时期 + 已确认导出参数 → 批量能力检查 → 批量计划 → 用户确认 → 后台下载 → 结果摘要。

复杂 GIS 分析仍保留脚本和 MCP 能力，进入该分支须有相应用户任务、缺少的业务能力和明确的完成标准。

## 1. 工具指令与恢复后的实际能力不一致（P0）

**证据**

- R 中继续走廊下载用了 58 次工具调用，包含 26 次本机命令；大量操作用于找已生成的几何。
- R 第 865–904 行：模型寻找 `mcp_result_export`，将它误当成 OpenLayers MCP 工具调用，收到 `UNKNOWN_MAP_TOOL`；随后拿旧执行引用从 offset=0 读取，收到 `INVALID_MCP_RESULT_PAGE`。
- R 的原生 `session_meta.dynamic_tools` 有 70 个工具，缺少 `mcp_result_export`。当前生成的本机工具文件有 71 个，包含该工具；H 新会话的原生清单也包含它。
- 当前 `codex-host.mjs:359` 只在 `thread/start` 传入 `dynamicTools`，`thread/resume` 没有更新动态工具。旧会话继续时保留旧契约的风险仍在；更新本机 JSON 文件不能证明旧线程已获得新工具。
- H 第 1058 行：`view_image` 实际被拒绝，原因是当前模型不支持图片输入。此前模型已多次截图，并开始查找图片；其“目视核对”的能力与真实模型能力不一致。
- H 第 896、897 行：两次把 `source_configure` 发给图源 Creator MCP，均返回 `SOURCE_TOOL_NOT_FOUND`，再改用顶层工具才保存成功。

**建议**

- 对每个原生线程记录工具契约版本；恢复时核对原生模型实际可调用的工具，不只核对宿主文件。
- 根据捆绑原生协议支持情况更新工具；若协议无法原地更新，采用可保留已确认参数、执行记录和任务 ID 的迁移方式，不重做下载。
- 分开应用操作工具和第三方 MCP 工具；返回精确入口和参数，避免让模型猜命名空间。
- 由实际可用工具和模型输入模态生成指令。图片不可读时，不要求模型做目视核验，不让它为了看图转入像素实验。

**验收**：70 工具的旧会话升级后，可直接导出原几何；找不到工具时明确报告能力缺口；不扫描应用目录、数据库和原生会话日志补洞。

## 2. 空间数据没有形成可连续处理的业务引用（P0）

**证据**

- R 第 917–1074 行：为了继续“沿途 1 公里”，模型列举应用数据目录、读取执行数据库、查看宿主实现，最后从原生 rollout 找到路线坐标。
- R 第 918 行目录输出原始计数达 239,076 tokens，保存的工具文本已经截短。这是命令工具自己记录的输出计数，不能直接当成全部送给模型或实际收费的 Token 数。
- 最终通过脚本完成路线投影、1000 米缓冲和保存，说明这是需要固定业务入口的常见操作。

**建议**

- 路线结果自动保存为账号/会话归属的数据引用，附原始坐标系、几何类型、来源、点数、数据完整性和散列。
- 原生增加“从路线/图层引用生成距离缓冲区”的操作，返回 `boundaryId`；完整坐标在本机处理。
- 地图显示、缓冲分析和影像计划使用同一引用，避免导入/导出/分页时重新抄坐标。
- 引用失效返回可修复的明确原因，禁止以扫描内部日志作为正常恢复路径。
- 缓冲距离以米处理并明确所用投影/计算方法；图源坐标系、分析坐标系和最终导出坐标系分别记录。

**验收**：已保存路线 → 1 km 缓冲范围 → 影像计划，不依赖命令行寻找几何，不把几百个坐标点送回模型。

## 3. 等待确认被当成错误重试；批量前置条件触发大量失效调用（P0）

**证据**

- H 历史影像请求用了 124 次工具调用；其中 `plan_imagery` 25 次，最终生成 13 期计划。
- H 第 482–494 行：一批 13 次规划中，首个得到计划，另外 12 个返回 `REPLAN_AFTER_USER_INPUT`，随后第 527–538 行重规划剩余年份。
- H 第 569–581 行：全部计划已明确返回 `permission=confirmEach` 和 `requiresPlanConfirmation=true`，模型仍对 13 个计划逐个调用 `jobs_start`，全部 `APPROVAL_REQUIRED`。
- R 中规划走廊后也尝试启动，两个轮次各得到一次 `APPROVAL_REQUIRED`。

**原因和建议**

- 用户回答后禁止执行旧参数是必要保护，应保留。
- 在发送一批计划前先解决 CRS、格式、依赖、权限和最新需求版本；冻结一份有效参数，再由批量操作创建计划。
- 对时相列表提供批量规划，返回成功、失败和需要用户选择的项目；这与现有“多个范围”的批量工具是不同维度。
- 返回结构化 `awaiting_user_approval`，并提供批量确认入口；确认具体计划集合、参数和散列，不能擅自升为完全访问。
- 在等待确认时结束模型执行，后台事件负责后续状态；确认、暂停、完成等正常流程不标成异常记录。

**验收**：13 期任务只对有效参数规划一次；确认模式下无 13 次必然失败的启动；参数改变后旧计划不可误启动。

## 4. 任务意图、进展和完成标准不够具体（P0）

**证据**

- “看起来好像没有明显偏移呢”引发 29 次工具调用，其中 23 次本机命令；原生账单记录 31 次模型请求、30 次扣费，共 8,749.5472 Credits。
- H 第 972 行直接开始“实测核对”；随后下载瓦片、写脚本、运行像素统计和互相关。

- 当前 `execution_safety.rs:90–110` 检查同一工具参数与结果指纹。不同计划 ID、Registry 查询词或不断改写的脚本都可能被视为新操作，无法保证业务有进展。

**建议**

- 明确当前请求类型：聊天反馈、配置、规划、执行、核验。普通反馈不派发动作工具；进入新的分析目标需要用户实际请求。

- 错误按“目标 + 错误类别 + 能力/配置版本”归并；更换查询词或写法不自动视为突破。
- 达到完成标准就总结，等待下载由后台负责。授权的长任务有进展时继续；可选累计预算跨继续消息生效，不增加默认 12 次或单轮费用硬截止。

**验收**：同一句普通观察不启动脚本；三种不同写法得到同一能力/权限阻塞时停止无效探索；跨消息继续不重复已完成步骤。

## 8. 错误处理要有业务分类（P1）

**证据**

- R 一次 Mapbox 接入请求中有 6 次 `REGISTRY_UNAVAILABLE`；失败来自同一 Registry 可用性问题，换查询词没有解决网络。
- 当前查询函数每次可再请求主站 10 秒、备用入口 20 秒，没有在这里看到按上游可用性缓存失败的机制。
- H Nominatim 返回 403 被标记为 `INPUT_AUTH_REQUIRED`。当前 `online_inputs.rs:120` 将 401/403 一并映射认证错误；未保留足以判别凭据问题和服务拒绝/访问策略的原因。
- R 写入审批通道两次失败后继续寻找其他数据入口；H 也有写文件失败后更换执行形式的探索。

**建议**

| 类别 | 处理方式 |
| --- | --- |
| 用户待回答/待确认 | 保留步骤和参数，等待；不计为执行错误，不尝试绕过 |
| 工具不存在/模型不支持 | 校验精确入口；一次有依据的修复后仍缺失则明确停止该分支 |
| 凭据、权限、审批通道不可用 | 原生显示需要的操作；配置不变不重试，不寻找绕过路径 |
| 网络超时/429/可恢复的 5xx | 有界重试、退避、缓存和可用节点切换；失败按上游归并 |
| 空几何/不支持所需数据 | 标记业务能力缺口；使用已支持的适配器或让用户选择有影响的替代方案 |
| 参数解析/脚本错误 | 按错误类别修复；只在原任务范围内继续，不把不同错误文本当作完成进展 |

Registry 的官方预设当前已存在，这是已有补救；还需要可用性冷却和候选 ID/URL 确认的一致契约。

## 第一批实现顺序与回归标准

1. **线程工具契约同步**：旧会话恢复能获得已声明的新工具；缺失工具/不支持图片输入不会触发目录扫描或替代实验。
2. **路线引用 → 缓冲区 → 边界链路**：数据完整性和 CRS 不变，几何保持本机处理；跨继续消息可复用结果。
3. **批量计划前置检查和等待确认状态**：13 年任务不产生 12 个失效规划与 13 个必然失败启动；仅执行已确认的具体参数集合。
4. **业务进度和错误归并**：普通观察不调用工具；改变查询词/脚本写法不能清除相同能力或权限阻塞；有效长任务继续执行。
5. **原子地图操作、坐标转换事实和精简工具发现**：切换保留成果叠加；模型解释与实际变换一致；只返回需要的 schema。

用现有真实记录建立不扣业务额度的回归场景，至少覆盖：闲聊、同名地点、改分辨率、旧线程新增工具、13 时相计划、待确认、失效结果引用、Registry 超时、模型不可读图片、已完成任务继续、近似公交几何。用真实工具/台账断言完成标准，不只断言模型输出里出现“成功”。

记录阶段推进次数、同错误重复数、重复询问数、任务工具数、模型请求数、实际结算费用和缓存比例。不要只追求调用次数少，也不要在没有运行证据时承诺具体节省比例。
