# 任务查询由模型回答

## 原因与修正

之前工具回调返回 `finishText`，Codex host 在下一次模型请求中直接输出该固定文本，跳过了模型生成。用户看到的重复“状态已更新”因此确实不是基于本次查询的模型回答。该实现已撤销。

- 删除 Codex host 的 `localFinish` 拦截和固定回答生成路径，前端不再返回 `finishText`。
- 原有引擎的任务交接也继续执行工具结果到模型的后续调用。
- 本机后台监控只更新进度卡片；任务状态工具提供实际进度、记录时间与执行进程是否运行。
- 当记录仍为 downloading，但本机没有对应执行进程时，界面和工具报告 interrupted，并保留原记录状态供核对。

## 实际验证

在原用户会话、真实 GeoD 账号与 DeepSeek 模型上查询一次任务，未启动、恢复或取消下载：

1. 模型生成 `b2c704a8-56ea-4902-8ddd-fb6c0daa9c27` 调用 `jobs_get`。
2. 工具结果返回模型；生成 `094888df-d25b-459d-ad06-e4fdd4b5381a` settled，产生实际最终回答，无追加工具调用。
3. 模型根据结果报告 448/600、75%、已中断、执行进程未运行。右侧任务面板同时显示已中断。
4. 输入框正常恢复可用，约 8.5 秒完成。

审计与截图：`evidence/codex-model-reply-2026-10-01.json`、`evidence/codex-model-reply-2026-10-01.png`。

前端构建通过；常规测试 46 个通过、1 个按默认配置跳过；指定真实 Codex 可执行文件的工具循环测试与任务状态测试合计 7/7 通过。工具循环测试刻意提交旧 `finishText` 字段，确认它不能替代模型回答。

开发版通过前端热更新和每轮读取 host 源码生效。未重新安装、未发布服务器。
