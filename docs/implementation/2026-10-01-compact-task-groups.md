# 聊天中的紧凑任务入口

## 布局

- 单任务只显示行政区划或数据名称、当前状态和查看入口，外框高 44px。
- 同一回答的多个任务合并成一个任务组，显示数量、前两个名称的预览和状态汇总，外框固定高 60px。任务数量增加不会继续撑高聊天记录。
- 每个入口继续绑定原回答，保留已有名称、归属和账号/会话隔离记录。
- 确认、开始、丢弃、取消及路径/计划详情集中在右侧任务面板。点击任务入口打开右侧并筛选对应任务组，可通过“查看全部”回到当前会话列表。
- 混合状态的任务组优先打开尚未结束的成员；保留组内已有选择。状态摘要来自任务队列与本机状态，没有预编写 AI 回复。
- 切换会话、账号或生成新计划会清理任务组筛选。已关闭右侧时再次点击同一任务也能重新打开。
- 保留进入动效；悬浮只改变背景。浅色、暗色及 320px 对话面板使用 14px 字号，名称截断后可通过提示查看。
- 更新模型的界面说明与内置 Creator 文本，逐次确认引导至右侧任务面板。

## 验证

- `npm run build` 通过，保留原有 bundle size 提示。
- `node --test test/task-summary.test.mjs test/plan-presentation.test.mjs test/task-queue.test.mjs test/chat-work.test.mjs test/agent-workflow.test.mjs`：29/29 通过。
- 使用实际 ChatTranscript、TranscriptTaskGroup、TaskPanel 组件的独立浏览器 fixture：单任务 44px，8 项和 32 项任务组均为 60px，组数保持两组；32 项右侧队列高 274px，内部滚动。
- 320px 对话宽度下入口宽 268px，无横向溢出；字体 14px。浅色与暗色截图均已检查，浏览器没有 warn/error。
- 点击 8 项入口后右侧只显示本轮 8 项；收起后点击同一入口仍能打开。模拟批量丢弃后入口显示“已结束 8”，上一轮河南任务仍待确认；查看全部显示当前会话 9 项、待处理 1 项。
- UI fixture 的操作回调为模拟状态，未调用真实下载或模型，不修改用户聊天数据。真实批量任务动作继续使用原有本机控制器及单元测试覆盖。
