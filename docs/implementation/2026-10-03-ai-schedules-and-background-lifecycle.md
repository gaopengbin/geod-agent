# AI 定时执行与后台生命周期候选

本地开发候选，未发布线上服务或安装新版。

## 可操作入口

- 对话中请求稍后执行或周期执行，由模型调用 `ai_schedules_create` 实际保存。
- 右侧「任务与成果 → 定时 → AI 定时执行」新建、暂停、查看结果、取消本次或重试。
- 一次性、每小时、每天、每周；底层支持以秒表示的周期。
- 关闭窗口后，独立本机后台继续执行。退出后台、休眠或关机时停止触发；重开会补执行一次到期指令，错过的周期合并。未完成或等待用户的同一任务不重复触发。
- 下载任务仍交给独立下载进程监控，AI 不反复轮询刷屏。

## 执行与恢复

SQLite 持久化任务、执行状态、工具结果、命令记录、模型结果和权威用量。后台按当前账号及工作区权限执行，凭据继续由本机连接器读取。每个定时任务有独立 Codex 线程，重试保留原线程；桌面对话线程与后台任务线程分离。

需要连接授权、输入、确认或地图视图时，本次转为需要输入。后台异常退出时，正在执行的记录标为中断，用户核对后重试，避免自动重放已产生副作用的操作。独立下载任务保留自己的续传与核验记录。

「暂停」只停止后续触发，「取消本次」中止正在进行的 AI 执行。AI 已启动的下载由任务区单独取消，操作语义与实际进程一致。

## 实际验收

- `artifacts/background-lifecycle-20261003/acceptance.json`：真实本机下载器完成通信认证、单实例、协议错误、暂停重开续传、取消、后台意外退出后恢复，以及显式停止后的轮询行为。延迟瓦片服务是明确声明的本机测试服务。
- `artifacts/ai-schedules-20261003/acceptance.json`：实际关闭桌面，真实模型读取随机文件编号及 GeoJSON 文件名，保留模型用量；重开读取原结果。相同创建请求返回原记录，改变指令的相同执行标识报冲突。
- `artifacts/ai-schedules-20261003/controls-acceptance.json`：中止正在运行的真实命令且目标文件未写入；下载权限暂停后人工重试真实完成 GeoTIFF；不同任务线程隔离；真实产品对话创建定时任务，界面暂停生效。
- 本机编译及 TypeScript 检查通过。

补跑策略已实现，但长期停止、多周期合并和干净 Windows 安装启动仍在发行验收清单。外部连接器是否可用取决于其实际认证及服务状态；无界面的后台无法操作桌面地图视图。

另修正恢复下载的误报：计划中派生的瓦片边界在 JSON 往返后可能相差一位浮点精度。瓦片索引和尺寸仍严格匹配，派生边界使用机器精度范围比较，避免把原计划误判为已变更。
