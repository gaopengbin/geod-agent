# 原生窗口调用阻塞修复

本次针对用户反馈的 GeoD Agent 开发窗口几乎无响应。修复版已构建、启动并在原窗口配置上验证；未发布安装包，未修改线上服务或额度。

## 观察与修复

现场系统 CPU 约 6.3%，可用内存约 24.1 GiB。开发服务立即返回，WebView JavaScript 定时器与动画帧正常，但 `desktop_runtime_capabilities`、`background_status`、`jobs_active`、`auth_status` 四个调用在 2.5 秒观察期限内均没有返回。这支持把问题定位到原生调用链，而不是仅凭截图把它认定为渲染失败。

代码检查发现前台默认同步执行原生处理函数；登录状态查询会读取授权锁并在访问令牌过期时同步刷新，身份网络请求的超时为 55 秒。本机任务的 `current_user_id` 也会触发联网刷新。Tauri 的[命令线程说明](https://v2.tauri.app/develop/calling-rust/)确认同步命令默认在主线程执行。

- 增加统一前台 IPC 派发器，把同步原生工作移到阻塞工作池，保留已有的后台路由及异步命令行为。
- 未注册命令明确返回 `COMMAND_NOT_FOUND`；处理函数意外退出时返回执行结果待核对，不能让调用永久挂起，也不自动重发可能已产生效果的操作。
- 本机用户归属只读取当前凭据快照，身份来源和用户 ID 仍须匹配；不再为了读取本机任务而先联网刷新。
- 登录状态查询读取本机登录记录，不排队等待轮转令牌刷新。模型、支付和其他远程请求仍沿用原有受保护的令牌刷新与服务器授权，没有把过期令牌当作有效云端授权。

## 恢复与验收

重启前保存了界面存储快照和只读 SQLite 备份，输入框没有未发送草稿。读取任务库确认没有正在执行的下载、数据处理、后台命令或子任务后，仅关闭本次开发窗口及其空闲后台，保留其他产品进程、所有任务记录和成果。

修复后原生窗口 PID `16012`，后台 PID `35788`；接口实测：

| 接口 | 修复前 | 修复后 |
| --- | --- | --- |
| 运行能力 | 超过 2500 ms 尚无结果 | 3 ms |
| 后台状态 | 超过 2500 ms 尚无结果 | 7 ms |
| 活动作业 | 超过 2500 ms 尚无结果 | 6 ms |
| 本机登录状态 | 超过 2500 ms 尚无结果 | 2 ms |

用本机只读模型目录探测接口模拟 16 秒网络等待；未保存测试渠道，未调用真实模型。等待期间另外四个本机接口在 4–8 ms 返回，未知命令在 3 ms 明确拒绝。测试前后渠道数量一致，测试服务器已关闭。

通过 Computer Use 实际点击图源管理和返回原会话，窗口均正常切换；中文测试输入立即可见。自动化清空输入时意外提交了一条测试文字，被本机 `SPONSOR_UNAVAILABLE` 检查拒绝；随后在确认无执行、仅新增这一条测试输入的条件下，恢复该会话的测试前快照，保留审计记录，没有改动原用户消息或其他会话。最终输入框为空，测试文字不在会话中。

新增派发器阻塞隔离、异常结果和离线用户归属测试；原生库共 209 项通过，23 项按既有条件忽略。故障现场、前后响应、慢接口、任务库快照、恢复回执保存在 `artifacts/diagnostics/20261027-unresponsive/`。部分旧会话仍固定到已停用的赞助渠道，这是模型选择状态，不作为窗口响应已恢复的依据，也未擅自更改其渠道选择。
