# 本机扫描文档识别

日期：2026-10-04，2026-10-05 核对后续加密文档验收。以下是开发程序的实际验收；本轮没有重新安装、发布服务或启用收费。

## 已实现

- 对话附件菜单新增“添加文档或扫描件”，支持 PDF、PNG、JPG/JPEG、WebP、BMP、TIF/TIFF，以及原有 Office 和文本。原有“添加图片”仍用于模型视觉输入。
- PDF 优先读取原生文字；缺少文字的页面使用本机 OCR。混合 PDF 保留原生页面文字，并按页补入扫描内容。多页 TIFF 按原始页面顺序识别。
- 附件沿用紧凑列表，只补充“本机识别”状态。原文件、识别正文、实际 OCR 页码和引擎信息分别保存；低置信度、空白和截断如实提示，不把正常识别标为异常。
- 批量输入逐项保存成功结果；后续文件损坏不会清空已经成功的附件。解析期间切换会话，草稿仍归原会话；解析完成前再核对当前账号。
- Agent 通过 `attachment_read` 分页读取识别正文。识别在本机执行；发送对话时，读取的文字会交给所选 AI 渠道。识别内容是资料，不能成为工具授权。

## 本机运行资源

采用 RapidOCR 3.9.2、PP-OCRv6 小模型、ONNX Runtime 1.30.0 CPU 和 pypdfium2 5.13.0。固定三个本地模型路径，不在实际识别时联网下载模型，不依赖用户安装 Python、Office 或 GPU。

`vendor/ocr-runtime.lock` 固定安装包及哈希；`vendor/ocr-sources.lock.json` 固定补充的完整许可证来源和哈希。应用准备脚本写入独立 `ocr-runtime` 资源目录，清单逐项校验 2,225 个文件、268,587,961 字节（约 256 MiB）。本机七组运行资源的 24,407 个文件通过整体校验。这是开发资源验收，没有生成新的安装版。

原生首次使用校验完整清单和文件 SHA-256；缺失、篡改、路径逃逸返回明确的 `ATTACHMENT_OCR_RUNTIME`。附件记录新增可选 OCR 字段，兼容原记录，保留原文件 SHA-256。分支和完整备份同时保留原文、识别文本及元数据。

## 当前边界

- 单个附件 32 MiB，单次最多 8 个、合计 64 MiB。每文件最多尝试 50 页 OCR；超过后保留已读取内容并标记截断，最长执行 180 秒。
- 原图片限制 2,500 万像素；PDF 渲染限制长边 2,600 px、约 600 万像素。测试短文件在当前 CPU 上约 2.3–3.9 秒，不据此承诺所有文档速度。
- 已实际验证清晰的中英文印刷文字；手写、更多语言、复杂版式尚未实际验收。原生文字较多且同页带扫描文字的复杂混合页面仍有漏识别风险。
- OCR 正文尚无发送前专用编辑器；用户可在消息中说明修正。加密 PDF 已另行接入本机密码表单，实际 AES-256 扫描页解密及 OCR、错误密码清空重试、取消和会话隔离通过；密码不传给模型。已验收算法、密码保存检查及未支持的证书/企业权限解密边界见 [加密文档](2026-10-04-encrypted-documents.md)。
- 常见旧版 `.doc/.xls/.ppt` 已另行完成，见 [旧版 Office](2026-10-04-legacy-office-inputs.md)；现代 Office 和八种音频格式已有独立验收。
- 全新 Windows 验收按用户要求暂缓；没有执行系统重启或安装升级。

相关实现路径相对 `apps/geod-agent-desktop`：`src-tauri/src/attachment_worker.py`、`src-tauri/src/ocr_runtime.rs`、`src-tauri/src/attachment_inputs.rs`、`src/document-attachments.tsx`。准备与验收脚本位于仓库 `scripts/`。
