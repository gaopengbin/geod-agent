# 独立子任务 Agent

本地开发版通过真实 Codex 0.159.2 和托管模型运行独立文件分析子任务。它是 GeoD 的子任务执行层；没有直接启用 Codex 内部的 `multi_agent` 开关，也没有把普通回复模拟成 Agent 结果。

## 当前能力

- 主 Agent 可通过 `agent_tasks_spawn/list/get/read_file/cancel` 分派、查看、读取结果和取消任务。旧线程可从 `builtin-agent-tasks` 发现真实 schema。
- 每个任务有独立 Codex 进程、线程、工作目录、输入快照、事件和结果；仅复制明确选中的工作区相对文件。
- 3 个任务可同时执行。子任务的工具仅能列出、读取文件；获得当前工作区完全访问权限且明确 `readOnly:false` 后，可在自身目录写结果。
- 子任务不获得父目录、外部 MCP、地图、系统命令或递归创建 Agent 的能力。它适合文件分析、检查、报告整理；实际 GIS 连接、地图操作和下载仍由主 Agent 处理。
- 所有读取和操作按账号、会话、绑定工作区核对。输入总量 32 MiB / 16 个文件，文本读写单次 1 MiB，最多 256 个文件；拒绝穿越、绝对路径、链接和 Windows 重解析路径。
- 执行由独立后台持有。关窗继续；重开读取同一记录。意外退出保留中断状态，不自动重复执行。
- 右侧“任务与成果 → 子任务”提供紧凑列表、单个取消入口、实际结果与文件阅读。逐字输出和心跳不充当操作历史，聊天内不持续刷进度。

这些是 native 工具的目录与上下文隔离，不宣称是 Windows 操作系统沙箱。子任务不会覆盖父工作区；主 Agent 读取结果后是否采用，仍按用户任务处理。

## 实际验收

证据：`artifacts/agent-tasks-20261003-final/acceptance.json`，13 项通过。

- 两个真实 Codex 线程同时运行，分别读取随机文件编号、计算数值、写出正确文件；主对话在此期间仍返回真实模型回复。
- 从模型收据核对实际网关请求和已结算用量；不同子任务没有混用执行标识或线程。
- 相同执行编号重放返回原任务，更改指令被拒绝；跨会话获取、读文件和取消被拒绝。
- 实际模型调用只读写入工具后收到拒绝，目标文件不存在；启动时取消只影响对应任务。
- 主 Agent 在真实对话中启动两个任务，随后读取它们的真实结果文件，界面可打开保存文件。
- 实际关闭桌面窗口后继续生成多份文件；重开连接同一后台 PID，读取完整结果。

验收发现并修复了 Windows AppData 重定向造成的长目录问题，以及逐字输出挤掉操作历史的问题。引擎启动失败时保留本机日志，不再误报“缺少系统 Node.js”。

## 费用记录

子任务请求使用与主 Agent 相同的托管模型。每个任务有独立 native 执行收据，可以分别核对请求和用量；当前仍是不限测试额度、未启用真实扣费。正式收费时还需在账单展示层将主任务和子任务归为一个任务组，不能把分派动作当作没有模型成本。
