# 旧版 Office 附件

日期：2026-10-04。开发程序已实际验收，没有重新安装、发布服务或启用收费。

## 当前能力

“添加文档或扫描件”支持二进制 `.doc/.xls/.ppt`，与原有 PDF、现代 Office、文本、扫描件和音频共用紧凑附件列表、对话归属和 `attachment_read`。

- Word 读取保存的正文与 Apache POI 支持的文本部分。
- Excel 按工作簿顺序读取工作表、单元格地址、保存的值和公式。读取不重新计算：测试文件 B9 的保存值为 3、当前公式为 `8+9`，实际仍返回 3。外部超链接没有被访问。
- PowerPoint 按实际演示顺序读取幻灯片文本；已验证先创建的第二张重排为第一张后，读取顺序同步改变。代码也读取已有备注，复杂备注和表格尚未单独验收。
- 保留源文件及 SHA-256、提取正文和元数据；失败清理暂存文件，批量后项失败保留前项。已发送附件不可被其他会话读取，原生分支和完整备份保留原文件。
- “公式未重新计算”作为信息提示保留在工具结果和悬浮说明中，正常表格不显示异常颜色。

## 本机运行资源

使用 Apache POI 5.5.1（来自 Apache Tika 3.3.2 发行包）及独立 Eclipse Temurin JRE 21.0.12.1+1。Tika 3.3.2 是目前官方仍维护的 3.x 版本，见 [官方发行说明](https://tika.apache.org/download.html)。

没有系统 Office/Java 安装依赖。固定运行包地址和官方校验值，保留完整许可证；当前 318 个文件、217,248,262 字节（约 207.2 MiB）逐项校验。Windows 10/11 使用系统自带 Universal CRT，运行包不再复制 JRE 归档中的冗余 `ucrtbase.dll`；没有修改系统运行库。实际桌面直接启动私有 JVM，清除继承的 JVM 配置，只使用本机受控文件路径；不启动 Office、宏、公式求值器或外部转换器。解析进程独立、堆容量 384 MiB，超时结束对应进程。

源码与资源：`src-tauri/src/GeodOfficeReader.java`、`src-tauri/src/legacy_office_runtime.rs`、`vendor/legacy-office-runtime.lock.json`、`scripts/prepare-legacy-office-runtime.py`。应用路径相对 `apps/geod-agent-desktop`。

## 修补记录

1. 首轮本机解析通过、桌面启动解析失败。实际日志证实应用资源路径含 Windows `\\?\` 前缀，JVM 类加载器无法处理；独立复现 `ClassNotFoundException` 后，修正 JVM 路径表达，再通过实际桌面验收。启动故障现在返回运行环境错误，避免误报用户文档损坏。
2. 首轮 UI 验收把两个同名草稿当成一个，以及过早读取旧错误提示；改为按原生附件 ID 定位、等待实际批次结束，沿用同一测试会话完成。
3. 模型第一次回答把一次全文读取称为“均为单页”。工具的工作表/幻灯片数量一直为 2；已补充 `units/unitLabel` 和字符分段语义，并保留原回答。第二次真实模型读回两工作表、两幻灯片及缓存值，结构化结果正确；自然语言仍可能把一次返回称作“单页”，不能以此替代原文件数量。
4. 原同步脚本会用 63 个网关工具覆盖 69 个桌面工具。现拆出六个本机工具定义，构建先同步且增加校验，防止附件和 SQL 工具在重建后丢失。
5. 后续数据库构建中，本机创建/复制名为 `ucrtbase.dll` 的文件返回 Windows 错误 5，其他文件可正常写入；具体系统原因未确认，没有修改 Windows 防护设置。按照 [Microsoft 官方运行库说明](https://learn.microsoft.com/en-us/cpp/windows/universal-crt-deployment)，Windows 10/11 始终使用系统 UCRT，现跳过归档中的冗余副本。调整后重跑 10 项实际 Office 解析通过；实际 JVM 模块记录确认加载 `C:\Windows\System32\ucrtbase.dll`。证据见 `artifacts/product-gaps-20261004/database-tls/build-recovery/`。原 319 文件记录对应调整前的历史版本。

## 边界

当前覆盖常见 Office 97–2003 二进制文件；更早版本、伪装成 `.doc` 的 RTF/HTML、复杂文本框/备注/表格及宏专用扩展名没有完整验收。读取不提供版式预览或编辑，也不保证恢复损坏文件。

加密 XLS 的拒绝已实际测试，尚无密码输入入口；加密 Word/PPT 需要另行验收。单文件 32 MiB、单次 8 个/64 MiB，文字最多提取约 200 万 UTF-16 单位；内容截断如实标记，解析最长 60 秒。全新 Windows 按用户要求暂缓；没有执行系统重启、安装或升级。
