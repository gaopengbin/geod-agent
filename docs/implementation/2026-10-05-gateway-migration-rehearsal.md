# 0.2.2 网关：正式账本快照的隔离升级与回退

日期：2026-10-05。正式网关只做只读观察，仍为 0.2.1；实际升级、回退和再升级均在本机 Docker 的隔离副本中执行。没有部署、重启正式服务、启用现金、发送真实模型请求或执行资金操作。

## 正式来源

10:01:32 UTC、10:09:46 UTC 与最终 10:16:16 UTC 的观察确认：

- 正式 PM2 为 `geod-agent-0.2.1-20261004`，PID `655682`、启动时间、版本目录和服务代码摘要保持。
- 既有支付状态/钱包接口未认证为 401；八条新历史/CSV 路由均为 404，没有扩大正式开放范围。
- 正式模型账本包含 185 次请求、553 条 token 用量记录；Credits 账本包含一次赠送、一次实际结算、一条历史预留和零笔现金订单/退款。
- 两份 SQLite 的表结构、所有原记录摘要和内存快照摘要在前后观察中一致；Nginx 路由字节摘要保持。

SQLite 以只读连接复制到内存，随后通过固定主机密钥 SSH 返回本机；未在服务器创建快照文件、读取秘密环境文件或修改任何记录。PM2 元数据在内存中用于选择服务，仅导出公开白名单字段，不保存环境值；先前回执的 `environmentSecretsRead: false` 字段过宽，后续工具改为明确记录未读秘密环境文件及未返回环境值，不能把它理解为没有读取 PM2 元数据。每份快照各自一致，**不声称跨两个独立数据库的原子快照**。数据在本机 `private-snapshots` 下，由当前 Windows 用户和 SYSTEM 的目录 ACL 保护，不纳入源码、发行归档、公开日志或文档。

首次来源观察错误要求服务入口直接位于发行根目录；实际入口在已核对发行目录内的服务子目录。修改路径边界判断后重新观察，失败资料保留，没有将它记为产品故障。

## 实际归档演练

使用已经固定并实际核验的两个 Linux x64 归档，容器不接公开网络、不安装依赖、不继承正式密钥。只从归档解出的模块启动真实 Node 22.23.2 / SQLite / HTTP 网关；现有账号的认证由本机测试适配器返回，未冒充真实 OAuth 或再次调用真实模型。

| 阶段 | 结果 |
| --- | --- |
| 0.2.1 快照 → 0.2.2 | 185 次请求及 553 条用量全部逐字段保持，赠送、结算、分配、余额和所有其他原行保持；新增八条只读路由通过。 |
| 0.2.2 副本 → 0.2.1 | 旧版实际启动并读取同一副本；赠送与余额不变，新增历史接口如实返回不可用，原数据没有退回旧备份。 |
| 再次升级到 0.2.2 | 原记录和余额继续保持；查询/导出与首次升级相同，赠送仍只有一条。 |

每阶段多次读取钱包、状态及历史。对所有旧表的旧列内容做完整行集及重复次数摘要核对；唯一允许增加的是 `geod_payment_meta` 中一个格式合法的 `credit-history-cursor-key`，旧版本保留它，不重复发放额度。

新历史包含一条已结算用量、零条当前有效预留，以及空的现金订单/退款。账本中原有一条已释放历史预留仍逐字段保留；它不是当前预留列表的项目。首轮演练错误地将所有历史预留作为当前预留预期，失败回执保留，修正的是验收依据。

四类完整 CSV 的行数、BOM、长度及 SHA-256 符合实际响应；两次升级的导出字节摘要一致。现有生产账号编号不出现在导出内容中。源快照只读挂载，演练前后字节摘要保持；各轮拥有的容器退出并删除，其他 Docker 服务未停止。

本轮没有使用正式的结果加密密钥，因此只证明历史加密结果的原字段保持，**没有重放和解密旧模型回复**。既有协议样本中的 137 笔现金记录全量分页/导出证据仍单独保留；正式快照没有真实现金订单，不能借本轮宣称现金迁移或资金回调验收。
