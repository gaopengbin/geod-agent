# 通用数据库证书与双向 TLS

日期：2026-10-04。使用开发模式、本机独立数据库及真实 Codex / DeepSeek 验收；没有重新安装、发布网关或启用收费。

## 接入范围

保留 PostgreSQL / PostGIS 原有证书连接。通用 SQL 接入固定版本 DBHub 1.4.0，增加原生 CA、主机验证与客户端证书配置：

| 数据库 | 加密 | 验证 CA | 验证主机 | 客户端证书 |
| --- | --- | --- | --- | --- |
| MySQL / MariaDB | 支持 | 支持 | 支持 DNS 和 IP SAN | 支持 |
| SQL Server | 支持 | 通过完整验证模式 | 支持 | 此版本不提供 |
| Oracle Thin | 支持，始终验证证书链 | 支持 | 支持 | 支持 PEM 钱包内容 |

MariaDB 实例使用 MySQL 兼容连接与 mysql2 驱动实测。SQL Server 没有单独的“只验证 CA”选项。Oracle 的“加密连接”仍会验证证书链，私有证书需要提供 CA；没有把该模式宣称为跳过证书验证。

数据库设置允许选择 CA、客户端 PEM 证书及未加密 PEM 私钥。CA / 证书各限制 256 KiB，私钥限制 64 KiB。客户端私钥只显示文件名；关闭表单清除未保存的密码和私钥。没有添加将这些内容粘贴进聊天的入口。

Agent 使用 `sql_connection_connect` 读取用户提供的工作区相对连接 JSON。缺少认证或证书验证失败时，前台打开原生表单，填写后继续同一轮真实模型流程；后台需要补充认证时返回 `USER_INPUT_REQUIRED`。模型参数不能直接提交密码或私钥。

密码保存在 Windows 凭据库，客户端证书与私钥使用账号和连接编号绑定的 DPAPI 文件。保存的 CA 是公开证书。工具结果只提供连接引用及 `customCa`、`clientCertificate` 标记。本轮最初备份只保留连接配置和 CA；随后在加密私钥验收中，升级备份已增加系统加密的 `.client-tls`，仍绑定原 Windows 用户及连接位置。详见 [加密数据库私钥](2026-10-04-encrypted-database-keys.md)。

## 驱动修补与临时文件

DBHub 上游配置只允许部分数据库使用验证模式，当前在四个固定哈希的驱动模块中接入原生 TLS 配置。运行资源清单标记 `geodTlsExtension: 2`，同时保留上游来源和许可证。普通上游启动方式没有原生配置文件时保持原行为。

实际验收发现 mysql2 对 IP 地址连接没有执行期望的主机验证。已在固定哈希的 mysql2 模块中修补：SNI 仍按 DNS 地址发送，证书验证使用真实连接主机，单独验证 IP SAN。错误 CA、缺失私有 CA 和不匹配的 IP 主机均在真实数据库连接中被拒绝。

每次 MCP 会话在当前账号目录生成独立 TLS 临时目录，用当前 Windows 用户的 ACL 保护，持有排他租约，并通过清空继承环境后显式传入配置位置。序列化后的私钥缓冲区清零；会话结束移除临时文件。启动清理只处理经过路径检查、没有活跃租约的本应用目录。

## 实际验收

- MySQL 12 项、MariaDB 12 项、SQL Server 7 项、Oracle 9 项及 Oracle 双向认证 3 项，共 **43 项原生用例通过**。
- 使用四个官方数据库镜像运行独立、回环地址绑定的实例。证书由独立短期 CA 签发，服务证书只包含 `localhost`；通过可达的 `127.0.0.1` 检查主机不匹配。正确/错误客户端证书使用不同 CA。
- 四种数据库真实模型连接、表字段发现及查询通过，实际读回中文城市与数据库中的随机标记，没有让模型读取私有连接文件。
- 实际聊天在证书失败后打开本机表单，选择 CA / 客户端证书 / 私钥并输入密码后，同一轮 AI 查询成功。表单在 1000×720 中可滚动，操作栏固定。暗色中文截图已查看；浅色英文另通过实际账号菜单切换、真实未保存表单录入验证，不能用仅修改 DOM 主题属性的旧截图代替该验收。
- 实际关闭前台窗口后，独立后台 Agent 查询四个已保存的加密连接，返回四个真实随机标记；四次 SQL 工具调用成功。测试定时任务已停用。
- 完整备份 **1,210 项原生记录**，逐文件及界面记录哈希通过；连接引用保留，未包含本轮密码或客户端私钥。
- 原桌面及后台进程均退出后重新启动，七个保存的 CA / 客户端证书连接全部读回成功。

## 同时修复的界面等待问题

首次界面认证验收出现模型已有记录、界面未接上后续执行事件的等待。中断后重载并核对原生账本，实际重试通过；原始超时回执保留，根因仍未确定。

原生执行过程每三秒发送心跳。目前增加消息流静默检测：已经收到事件后，如果 45 秒没有后续事件，则停止当前等待并请求中断，即使账号状态探测仍响应也不会无限显示思考。健康心跳维持模型及用户输入等待；六项专项测试通过。事件回调异常也进入已有错误处理。

另通过实际界面确认了消息行与后附任务入口使用相同 React key 的问题。两者现在使用独立标识；重新载入后的语言切换与数据库表单操作无重复标识告警，原有界面记录没有重写。

## 验收边界

当前是本机实例和私有短期证书验收，尚未验收用户外部生产实例、企业证书轮换、Oracle Thick 驱动或 SQL Server Windows / Azure 身份登录。加密客户端私钥已另行完成解析、四种数据库、真实模型、后台及重启验收。SQL 仍是有限只读输入工具；普通属性表不自动变成裁剪范围。正式发行与全新 Windows 验收沿用产品缺口清单中的边界。
