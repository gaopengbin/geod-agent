## 真实付款与扣费

1. 验收期间仅允许当前账号购买一笔 ¥0.01 测试单，到账 10 Credits；其他账号的现有余额、用量查询和模型使用保持可用。
2. 真实支付宝签名查询通过。用户本人在正式收银台完成支付；实际公网签名通知和主动签名查询均有事件登记（`notify` / `query`）。付款页面打开不是到账证据。
3. 支付前可用余额 **92.85712 Credits**，付款后 **102.85712 Credits**。重复查询没有重复发放。
4. 向正式 Codex 模型路由发送单次短回复验收：输入 **49** token、缓存输入 **0**、输出 **40**，其中推理 **38**。输出包含推理，不重复相加计费。
5. `49 × 0.004 + 40 × 0.016 = 0.836 Credits`。正式收据扣除 **0.836 Credits**，验收后余额 **102.02112 Credits**，无超余额豁免；重放原 generation ID 没有再次调用或扣费。
6. 验收通过后切换正式三档 SKU，取消验收账号限制并移除测试 SKU 的购买入口；旧测试订单、回调和扣费记录仍可核对。

业务凭证保存在本地 `artifacts/monthly-payment-live-20261011/real-acceptance.json` 与 `production-verification.json`，实际签名通知和账本事件保留在服务端。HTTP 未授权访问返回 401。SQLite 检查正常，正式配置切换前后余额不变。

## 共享商户与恢复

保持既有运营侧每日 ¥1,000 分配：工具箱 ¥900，GeoD Agent 使用 GeoD 已预留的 ¥100。当前旧 GeoD 服务未配置支付宝现金购买；以后启用其他 GeoD 收款必须重新分配，不能让两个服务分别占满同一份额度。此分配不是支付宝承诺的商户额度。Agent 单笔不超过 ¥49，未扩大已确认商品金额。

部署时保留了前一 release、原环境文件及 Nginx 路由；部署校验失败时自动回退。现金支付关闭后的钱包读取与正常消费仍受回归覆盖。需要关闭收款时优先恢复无 checkout 配置或停用 checkout，保留当前商户账本和所有已支付记录；不要覆盖到账后的钱包备份。服务重启后保留当前原订单归属与幂等凭证。
