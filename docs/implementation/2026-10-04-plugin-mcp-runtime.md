# 插件 MCP 运行配置验收

状态：开发模式已验收。应用使用最新开发程序和前端热更新，没有重新安装或发布。

## 已接入

可移植 `mcp.json` 与 Codex `.mcp.json` 的以下配置进入实际本机执行流程：

| 配置 | 实际行为 |
| --- | --- |
| `cwd` | stdio 在指定目录启动；支持插件根目录变量。未声明时仍使用对话工作区。目录缺失给出明确错误。 |
| `env_vars` | 从本机进程环境继承所列名称；接受字符串或 `{name, source: "local"}`。未设置的普通继承变量不注入，显式 `env` 优先。 |
| `bearer_token_env_var` | HTTP 连接启动时，本机读取环境变量并添加 Bearer 认证。缺失时先返回配置错误，不发送请求。 |
| `env_http_headers` | HTTP 请求头的值从所列本机环境变量读取；界面和模型不接收认证值。 |
| `startup_timeout_sec` / `startup_timeout_ms` | 配置预算包含握手及首次工具发现；秒配置优先于兼容毫秒配置。支持小数秒。 |
| `tool_timeout_sec` | 覆盖工具调用期限。超时结果保持不明确，同一执行编号不会自动重试；stdio 进程会取消并回收。 |
| `enabled_tools` / `disabled_tools` | 在工具发现时筛选，同时在原生调用入口执行检查；排除列表优先。空允许列表表示没有工具可用。 |
| `enabled` | 添加插件时保留服务声明的默认停用状态，之后用户可按连接器启停。 |

原有 `command`、`args`、`env`、`url`、`headers` / `http_headers` 保持可用。带运行配置的服务通过 GeoD 原生连接器调用。进程参数、显式环境值和静态认证值进入系统凭据库；环境引用每次由实际前台或后台进程解析。启动环境没有整体继承桌面凭据。

插件预览显示工作目录、变量名称、超时、工具筛选及默认停用状态；长路径可换行，界面支持中文、英文、明暗主题和窄窗口。自定义连接器原生接口也接受可选的 `runtime` 参数；当前手动添加表单还没有独立的高级配置编辑器。

## 支持边界

- `env_vars.source: "remote"` 明确返回不支持；该产品尚无对应远端执行环境。
- 没有自动读取 `.env` 或安装插件声明的软件依赖。Windows 的包管理器脚本启动、平台注册 App 映射及其他 Codex 高级 MCP 配置继续推进。
- `mcp_tool` Hook Handler 尚未接入；本轮完善的是插件 MCP 服务的执行配置。
- 普通服务未声明超时时保留原来的原生默认期限。HTTP 工具的整体期限由 MCP 调用层控制，网络建连仍有单独期限。
- 系统凭据不会被复制进明文备份；本轮重启验收在同一 Windows 凭据库中完成。迁移到新设备仍需重新配置认证。
- 之前的 0.2.0 安装候选不包含本轮开发改动。
