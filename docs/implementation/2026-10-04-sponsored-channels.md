# 赞助模型渠道候选与实际验收

日期：2026-10-04。已在开发程序中完成，正式网关尚未发布这些改动。

## 当前能力

- 模型与渠道页并列显示 GeoD 托管、赞助、自有渠道。赞助显示供应方、模型、网站、累计用量、请求预留及当前可用额度；输入栏明确标注赞助。
- 供应方 Key 只由网关读取服务器环境变量。客户端只发送供应方 ID、模型 ID 和配置版本，不能指定赞助 API 地址或传入 Key。
- 网关按 GeoD 身份筛选可见渠道；停用、移除、配置变化和额度不足返回具体错误。已有会话、子任务和定时执行保留其渠道快照，不自动更换付款渠道。
- 赞助账本与托管额度独立。个人与共享预算在同一 SQLite 写事务中检查；进程中断且上游结果未知时保留预留，等待有证据的核对。
- 既有收费候选从服务端实际请求记录判断资金来源。赞助和个人 Key 请求不扣 GeoD 钱包，也不会生成 GeoD 钱包退款。
- 赞助的默认观察模式只记录用量；需要约束时由运营方显式配置个人与共享累计 token 预算。开发托管测试仍不限额。

赞助原生接口、图片和活动起止时间已在后续一轮完成，详见 [四种接口与实际图文验收](2026-10-04-sponsored-native-protocols.md)。默认预算仍累计计算；可选 UTC 自然月预算及界面刷新已接入，详见 [按月额度验收](2026-10-04-sponsored-months.md)。这里的额度是网关活动预算，不代表供应商账户的实时资金余额。

## 网关配置

`GEOD_AGENT_SPONSORS_JSON` 是运营配置数组；空数组表示没有赞助活动。Key 使用另一个仅服务端可读的环境变量。例如：

```json
[
  {
    "id": "partner-example",
    "name": "合作方模型",
    "description": "合作方提供的试用模型",
    "website": "https://partner.example",
    "baseUrl": "https://api.partner.example/v1",
    "apiKeyEnv": "PARTNER_MODEL_KEY",
    "allowedUsers": ["指定的 GeoD 用户 ID"],
    "enabled": true,
    "quotaMode": "observe",
    "models": [
      {
        "id": "实际模型 ID",
        "name": "模型名称",
        "contextWindow": 128000,
        "maxOutputTokens": 4096,
        "inputModalities": ["text"],
        "thinking": null
      }
    ]
  }
]
```

对所有用户开放须显式设置 `allowedUsers: ["*"]`。启用预算须设置 `quotaMode: "enforced"`，并提供正整数 `perUserTokenLimit` 和 `totalTokenLimit`。预算按供应方 ID 的累计记录计算，更新配置版本不会重置已用额度。

`GET /api/agent/sponsors` 使用既有 GeoD Bearer 认证，返回公开目录和服务端用量。Codex 生成请求可带 `sponsor: {providerId, modelId, revision}`；服务器选择实际地址、Key、模型和输出上限。调用者自报的资金来源不会改变服务器记录。

## 实际验收

证据目录：`artifacts/product-gaps-20261004/sponsored-channels`。

| 验收 | 结果 |
| --- | --- |
| 网关与收费候选回归 | 29 项通过；包含受控上游的认证路由、幂等、独立预算和资金来源检查。这部分不是模型实测。 |
| 原生目录与实际界面 | 5 项通过；其他账号渠道不可见，停用/未知模型返回明确错误。1000×720 明暗主题、英文与中文、焦点及操作对比度通过。 |
| 实际前台模型 | Codex + DeepSeek Flash 调用实际工作区工具，读回未放入提示词的随机 GeoJSON 文件名；两次模型请求均由赞助渠道结算。修改会话选择不改变正在执行的快照。 |
| 实际额度拒绝 | 仅在独立 QA 渠道配置 32 token 的边界。原生请求返回 `SPONSOR_QUOTA_EXCEEDED`，没有提交上游或切换托管渠道。正常 QA 渠道与开发托管保持不限额。 |
| 实际关窗执行 | 定时任务保存赞助快照后，将会话切为托管并关闭桌面。独立后台仍通过赞助模型读回同一真实文件名。 |
| 实际用量 | 前台与后台共四次请求，实际输入加输出合计 73,108 token；赞助目录累计值完全一致。托管已用与预留均为零。 |
| 备份与完整重启 | 1,018 项备份 SHA-256 全部校验；桌面、后台和独立 QA 网关重启后，公开缓存、选择、用量及加密保存的实际生成结果一致。 |
| 服务端版本变化 | 运营配置更新后，旧快照实际返回 `SPONSOR_CHANGED`，保持原始服务错误，不提交上游且不切换托管。 |
| 余额与英文显示修补 | 实际 32 token 显示为 32，修复原先被 K 单位舍入成零的问题；英文页面的不限额度已翻译。 |
| Key 与清理 | 本轮记录、公开缓存、真实前后台进程和完整备份无明文供应方 Key；3,577 个文件检查通过。独立 QA 网关与控制进程已退出，原开发网关保留。 |
| 原有数据 | 测试会话已归档到证据并从侧栏移除，测试计划停用；原 30 个会话严格一致，原活动会话、默认模型及外观语言恢复。原生验收记录和备份保留。 |

Key 检查还保留一次覆盖已有引擎目录的 277,318 文件记录；最终检查明确包含当时存活的桌面及后台进程和本轮完整备份。

## 转接问题修复

本机初测发现 Windows 系统代理拦截 Codex 与回环服务的连接。引擎进程现在为回环地址明确设置 `NO_PROXY`，外部模型请求继续由原生网络设置处理。

原生模型失败原因现在保留到对话结束，不再用引擎转接的通用错误覆盖它。明确的额度和渠道版本错误使用配套 Codex 可识别的终止分类，避免无意义重试。配套真实 Core 的三项受控协议测试通过；实际网关额度及版本拒绝另有上表的原生验收。

协议依据是固定的 Codex 0.159.2 源码（提交 `ff6aec96948b70d94983af2641a6b67c94faeff5`），`codex-rs/codex-api/src/sse/responses_error.rs` 的错误分类。不是修改 AI 的正常答案。

## 发布边界

验收渠道使用独立本机网关和已授权的项目测试 Key，不代表已经签订赞助合作或提供公共免费服务。原开发网关与正式服务未替换；客户端读取旧网关时保留原有托管与自有渠道。

这一候选没有安装程序、发布网关、启用真实钱包扣费或执行资金退款。正式供应方配置和发布须在确定活动范围后审阅授权。
