# 可恢复的任务记录清理

## 问题

影像计划只有前端本地丢弃标记，没有原生清理工具。Agent 无法列出并丢弃未启动计划；完成、失败等历史任务没有统一的清理入口。

## 实现

- 本机 SQLite 增加 `plan_visibility` 与 `data_task_visibility`，清理不删除计划、审批、作业事件、成果或瓦片缓存。
- 影像原生接口 `imagery_tasks_list`、`imagery_tasks_cleanup(action=discard|clean|restore)`，按当前账号、会话及保存的工作区校验归属。返回逐项成功及拒绝原因。
- 矢量、三维、在线数据原生接口 `data_download_cleanup(action=clean|restore)`，保留原始任务状态与清单，使用相同的归属检查。
- 主界面和独立后台、后台 Agent 执行器均接入；同步到 Codex 本机工具目录。模型返回仅含紧凑状态，不附加完整范围几何及本机路径。
- 队列每行清理按钮、多选批量清理、“已清理”列表恢复。运行/暂停的作业要先取消；仍在停止中的 worker 也不能清理。已启用定时模板、未结束定时运行须先处理定时设置。
- 影像清理与启动共享 SQLite immediate transaction；恢复作业时在 worker 锁内重查可见性。数据清理使用 immediate transaction，数据启动用状态与可见性的条件更新，防止跨进程竞态。
- 历史前端丢弃标记在原会话归属迁移后同步到原生库。任务实时上下文明确 `discarded/cleaned`；一般作业列表不再将已清理任务返回为可执行任务。

## 验证

- 前端任务队列、摘要 14 项回归通过。TypeScript 检查通过。
- Rust 影像恢复/清理、数据任务库、任务实时上下文回归通过，涵盖旧审批无法启动已丢弃计划、清理恢复保留事件、账号及会话隔离、定时模板保护等。
- 浅色、深色和 380px 页面组件测试通过：单项清理、影像与矢量混合批量清理、恢复、错误呈现、运行中任务无清理入口。
- 开发版实际调用本机命令，使用独立本地测试账号与新工作区：真实 Esri 小范围下载完成后，清理记录、重启独立后台、恢复记录，并逐字节比较成果文件一致。三维未启动计划清理与恢复通过。测试不调用模型，不修改线上账号或账本。
- 证据位于 `artifacts/task-cleanup-20261012/ui-acceptance.json`、`native-acceptance.json`，截图在同目录。

## 边界

这里清理的是任务列表记录，不负责释放成果文件或下载缓存的磁盘空间；成果与缓存继续由各自已有入口管理。未发布正式版本或修改线上服务。
