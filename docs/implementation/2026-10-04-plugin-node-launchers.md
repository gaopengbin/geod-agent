# Windows 插件 Node/npm/npx 启动验收

日期：2026-10-04。仅更新开发候选，未安装、发布或修改全局运行环境。

## 已实现

- 插件声明 `node` / `node.exe` 时使用应用配套 Node；`npm` / `npx` 及其 `.cmd` 写法直接交给配套 Node 和固定的 npm CLI 文件运行。配置中的参数仍是独立数组。
- 明确选择本机 `npm.cmd` / `npx.cmd` 路径时使用该安装目录的 Node 和 npm CLI，不执行 shim 内容。其他 `.cmd`、`.bat` 和 `.ps1` 文件仍须通过明确运行器配置。
- 选中的 Node 目录加入工具进程 PATH 首位，后面保留已配置的 PATH，使 npm bin 和工具的 Node 子进程使用同一运行环境。
- 前台、工具发现、后台定时使用相同原生启动逻辑，沿用独立工作目录、凭据库和超时。Windows 进程组负责关闭工具及后代进程。
- 配套文件缺失时返回可处理的错误；英文翻译同步补齐。

运行资源来自已固定校验值的官方 `node-v24.21.0-win-x64.zip`：Node v24.21.0、npm 11.19.0。npm 的 1,926 个文件、依赖和许可证全部保留，生成清单共 1,934 个文件。准备脚本验证官方归档、每项文件和实际 CLI 版本；应用资源目录的全部文件也已逐项校验。没有依赖开发机的全局 npm。

验收脚本最初错误地尝试重新绑定新会话工作区，已改为保留既有绑定并配置工具自身工作目录；另一次断言错误地把源资源目录当作运行目录，已改为验证桌面实际资源目录及完整校验值。两项都是验收脚本修正，没有额外付费模型重试。

## 范围

- PATH 隔离是本机实际桌面测试，不能代替全新 Windows 验收；后者按用户指示暂缓。
- npm/npx 可以运行用户选择的包。应用没有替用户预装所有第三方 MCP 包；首次获取远程包仍取决于网络、registry、包配置及工作区权限。
- 没有包装任意 shell 文本或隐藏执行另一版本的 npm。
- 旧 0.2.0 安装候选未重新生成；这轮能力目前属于已运行的开发候选。
