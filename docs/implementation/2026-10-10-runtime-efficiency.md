# GeoD Agent 本机等待、成果登记与按需上下文

## 本次范围

开发版运行层调整，保留 Codex 0.159.2 核心、原审批和权限机制。没有增加任务步数上限，也没有修改线上模型网关或扣费规则。

### 1. 后台等待

原生 `jobs_start` / `data_download_start` 成功后，宿主挂起该工具的返回，由 Rust 读取同一账号、工作区、会话绑定的真实任务状态。`jobs_get` / `data_download_get` 续接已经由用户确认的任务时采用同样机制。已完成、部分完成、失败、取消和暂停分别返回，不把非成功结果写成成功。

等待期间只发生本机读取和心跳，没有模型请求、人工拼接回复或固定等待时长。停止 AI 或用户改需求会解除等待，不会自动取消实际下载，也不会重新提交。后台连接中断返回未知状态，读连接监控不会启动或重启后台服务。

检查工作区和账号绑定后，原生文件核验器检查真实文件与当前计划。影像、矢量及三维清单统一为大小、SHA256、实际坐标系/尺寸等紧凑回执，本机路径不发给模型。

### 2. 自动登记

执行检查点自动绑定真实 jobId/taskId，保存原生核验回执。模型无需再通过 `runtime_task_update` 修改目标、填写描述性成果 ID 或尝试登记完成。该工具仍能按需发现，用于明确修改结构化任务要求。

完成登记只证明列出的原生任务资源，不自动宣称整个用户目标已经完成。多个下载中一个失败，不会被另一个成功覆盖；摘要回复仍由 Codex 根据实际工具结果生成。取消、未知状态及部分成果不能作为完整完成证据。

### 3. 按需加载

保留完整 Codex 会话文件、用户消息、已确认参数、工具调用与结果及原生权限。发送给供应商时：

- 已结束的历史工具调用不再自动启用对应整组工具定义；尚未返回的调用保持其契约。
- 当前任务和续接任务启用相关工具；所有原工具仍完整注册，可以通过 `runtime_tools_search` 恢复精确契约。
- 历史轮次的思考记录和未选中的技能目录转为按需读取，通过 `runtime_context_read` 分页获得原文；当前执行中的思考保留。
- 重复注入的检查点使用紧凑状态；完整证据通过 `runtime_task_state` 读取，详细审计继续保存在本机。
- Core 自身压缩请求保留完整输入，不按问候路径精简。

没有删除已确认坐标系、改变权限范围、用输出截断节省费用或限制正常任务的模型调用次数。

## 验证

- 55 项回归通过，包含真实配套 Codex、超过 12 次请求仍有进展的任务、权限检查、停止、重复副作用去重、当前思考保留、历史参数与工具契约恢复。
- 3 项 Rust 核验测试通过，覆盖非成功终态、路径清除、矢量 size 与三维 resources 清单适配。
- 已重启开发版并通过实际 WebView → Rust → Codex → 本机下载验收：6 个真实瓦片导出 GeoTIFF，实际 CRS 为 EPSG:4326，文件大小和 SHA256 核验通过。
- 这次下载的测试模型仅请求 2 次（提交及最终摘要）；执行器仅启动 1 次。等待和成果登记没有模型请求。再以逐次确认模式读取该已批准任务，同一 Codex 线程续接成功，没有重复提交或询问参数。
- 模型供应商采用本机确定性测试服务，验证原生链路及请求结构，不代表实际大模型回复质量评测。测试未调用托管模型，余额保持 0；原对话、地图、默认模型及原任务状态的读回一致。

验收回执：`artifacts/runtime-efficiency-20261010/final-native/acceptance.json`；真实成果：同目录 `download-proof.json`。测试下载与工作区独立保存，原用户文件未改动。
