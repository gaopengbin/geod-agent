# 会话与多语言推进记录

2026-10-04，2026-10-05 核对后续原生验收记录。目标模式下的开发版变更；本轮未重新安装或线上发布。

## 已实现

- 界面支持简体中文、English、跟随系统；独立设置 AI 回复语言，可跟随输入或界面。偏好在设备保存，切换立即生效。保持已有 LibreChat 界面规范。
- 界面词条使用中文原文作为标识，英文目录约 1,300 条。基础翻译使用真实 DeepSeek 生成，校验参数占位符并逐批保存；界面文案和历史系统提示翻译，不改写用户输入、模型回答或数据名称。
- 会话索引不再截断到 30 条；侧栏按工作区分段显示，历史页面支持全文搜索及继续加载。检索包含标题和消息正文。
- 会话支持重命名、置顶、归档/恢复、删除和导出/导入。JSON 导入创建新身份；JSON/Markdown 导出保留文本，不携带原生任务权限、工具调用授权、图源凭证或图片文件。
- 删除先保存删除标记，迟到的模型完成与恢复不会重建已删除会话。迟到结果也保留用户已经改过的名称、置顶和归档状态。
- 各会话独立保存忙碌状态、流式消息、请求队列、授权回应与停止句柄。异步回调绑定原会话，切换后不改写当前会话。地图和任务面板只在对应会话被选中时切换。
- 原生 Codex 引擎按账号及会话分别运行，独立配置目录和桥接端口。同一会话保持顺序执行，不同会话可以并行；排队消息在会话不显示时也继续。

## 解决的实际问题

1. 会话菜单的透明触发容器原本被行布局遮挡，修正了定位、点击区域和置顶行排版。
2. Windows 打包上下文会扩展 AppData 路径，新的会话目录导致 Codex 历史 SQLite 在恢复时无法打开。数据库改放在较短、按账号与会话隔离的目录；先保存原数据库和 WAL 的离线副本，保留原文件供恢复。使用 Codex 0.159.2 的 [CODEX_SQLITE_HOME 配置](https://github.com/openai/codex/blob/rust-v0.159.2/codex-rs/core/config.schema.json)。
3. 原生流式回复一次可收到大量片段，同步通知每个片段曾触发 React 最大更新深度错误。状态立即更新，界面通知按事件循环合并；真实模型复测没有页面异常。
4. 原生线程索引同时识别旧字符串记录和新带 rollout 路径的记录；恢复及分支使用真实 Codex 线程协议，不生成固定假答复。

## 待补验收与边界

- 旧单独停止/分支脚本的超时保持失败。2026-10-05 的全新完整验收已通过运行、原数据保留和清理，详见 [单会话停止与原生分支](2026-10-05-conversation-stop-fork.md)。「停止回复」不表示已终止 Codex 的背景终端；验收用长等待命令自然结束后再核对无残留。分支继承及重启读回也有上表中的独立通过记录。
- 当前历史索引仍整体从 IndexedDB 载入；分段显示不是后端游标分页。大量历史的启动性能需要进一步测量。
- 以前已被界面索引截断的记录不会凭空恢复；原生 Codex 线程及磁盘成果并未因此删除，可另行做有来源的历史恢复。
- 界面英文覆盖不表示所有供应商返回的错误或外部 MCP 内容都会翻译；这些原始内容保持可核对。
