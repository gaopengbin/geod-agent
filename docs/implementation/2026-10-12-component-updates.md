# 在线更新按组件复用运行环境

## 状态

本地实现和候选包验证；没有修改线上更新渠道，没有发布新版本。

## 分发格式与兼容

- 首次安装保留完整 NSIS 安装包和便携 ZIP，继续提供离线所需的六套内置运行环境。
- `latest.json.platforms.windows-x86_64` 始终指向完整安装包。旧版更新器无需识别新增字段，仍能按原有方式升级。
- 新版 `latest.json.componentUpdate` 指向独立签名的 `component-update.json`。它同时绑定发布版本、应用小安装包、六套运行环境的清单身份、压缩包字节数、SHA-256 和签名。
- 应用小安装包使用同一个已构建的主程序，仅移除六个大运行环境目录；没有把前端改成在线加载，也没有修改模型调用或任务规则。
- 新版更新器下载清单后，先用正式 Tauri 更新 SDK 验证签名和签名中的版本，再采信组件地址。应用包、组件包都用同一验证器检查，随后再次检查字节数与 SHA-256。
- 若签名正确但组件协议是未来版本，自动回到独立签名的完整包，避免新协议使旧客户端无法升级。签名错误不会降级跳过验证。

旧版 v0.2.4 第一次升级仍需完整下载，升级到含新更新器的版本后才能复用运行环境。新安装也继续使用完整包。不能将这个行为描述成旧版立即获得小更新。

## 本机执行流程

1. 校验签名清单包含六个完整、唯一的已知组件。
2. 对版本匹配的应用目录运行环境逐文件核验，并复制到应用数据目录下 `runtime-components/<id>/<manifest-sha256>`。已有有效组件直接复用。
3. 仅下载变化、缺失或损坏的组件。解压到同一磁盘的临时目录，拒绝绝对路径、父目录、链接、重复文件、未登记文件和超出清单尺寸的内容；逐文件核验后原子重命名。
4. 下载并验证小应用安装包。任何失败都不能登记为“可安装”；已核验的组件保留供重试使用。
5. 安装前重新核验完整组件、应用包与记录。沿用原有任务空闲检查、后台停机与会话/任务/设置备份流程。
6. 新应用的主程序在构建时嵌入所需的运行环境清单哈希。Codex、Node、Python、文档、pgEdge、DBHub、音频解析均接入同一组件查找路径。新旧组件目录共存，正在使用的版本不会被改写。

组件目录不包含账号密钥、会话数据或下载成果。首次迁移需要额外本机磁盘空间；失败不覆盖已核验的旧组件。暂不自动删除旧版本运行环境，避免破坏恢复所需的版本。

应用启动只核对所需清单身份，各功能保留已有的运行环境检查；更新迁移、解压和安装时才扫描完整文件，避免每次启动重新扫描 DBHub 的上万文件。

## 发布流程

`scripts/build-release-candidate.py --signed-update` 默认输出完整安装包、应用小安装包、六个组件压缩包及签名清单。私钥只传递给独立签名进程，构建/打包子进程继续只接收公开配置。`--without-component-updates` 可构建兼容旧流程的完整包。

发布时必须同时上传 `latest.json`、`component-update.json`、应用小包与六个清单引用的组件包及签名；保留 `latest.json` 的完整包地址。不要仅上传小应用包并将其放在旧更新器的默认平台地址上。

## 验证

- Rust 文件与缓存测试：原安装目录移除后复用；组件变化后旧版保留；损坏缓存修复；中断、损坏、超限、额外文件与路径拒绝；六套真实准备好的运行环境与构建清单一致。
- Python 发布测试：可重复组件归档、仅打包已登记文件、损坏输入拒绝、资源映射实际替换、完整安装包保留、旧更新字段保留、所有组件与索引单独签名。
- 原有 16 项签名密钥隔离回归。
- `component_update_acceptance` 使用实际生产组件更新代码、实际 Tauri SDK、官方 CLI 生成的临时测试密钥及本机 HTTP 服务。覆盖不变、缓存重试、只变一个组件、缺失组件、索引篡改、签名版本错误、压缩包篡改、传输截断和原有完整包模式。服务器请求记录核实运行环境不变时零组件下载。
- 该测试不执行安装程序、不访问生产账号、不消耗 Credits。真实运行环境文件在独立临时目录中核验；异常包使用不可执行测试内容。
- 从缓存实际启动 Codex 0.159.2、Node v24.21.0、Python 3.13.11；组件查找时应用目录为空，六套依赖均来自内容寻址缓存。

## 实测包体积

同一个已构建主程序对应的完整安装包为 257,075,492 字节，应用小更新包为 104,736,977 字节，下载量减少 59.26%。用 7-Zip 检查实际 NSIS 载荷，确认小包不包含六个运行环境目录，且提取的主程序 SHA-256 与完整包相同。证据：`artifacts/component-updates-20261012/package/package-acceptance.json`。

应用本身仍有内嵌行政区边界数据，因此小更新包不是几 MB。当前机制按运行环境组件复用，应用主程序仍整体更新，没有实现主程序字节级差分。

签名与下载证据：`artifacts/component-updates-20261012/sdk-acceptance.json`。隔离的实际 NSIS `/UPDATE` 安装已通过：新主程序安装成功，已有运行环境及记录保留；测试注册信息已清理。它使用独立 QA 产品注册名、进程名和 artifacts 内的安装目录，不启动用户已安装的正式版；结果保存到 `installer-qa-final/acceptance.json`。
