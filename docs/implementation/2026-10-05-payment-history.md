# 订单与退款完整记录：本地候选

本轮在独立候选分支 `codex/payment-history-candidate` 补齐订单与退款历史。主开发目录的多小时定时验收继续运行，现有桌面应用、账号和正式网关没有切换到这个候选。没有安装、发布或真实资金操作。

## 已补齐

- 「余额与订阅 → 支付记录」按订单/退款切换，每页 20 条，支持前后翻页、失败页原请求重试和全部/最近 7、30、90 天筛选。
- CSV 导出整个筛选范围，金额同时保留整数分与精确人民币值。退款含原订单、退款编号、创建和最近核对时间；不导出账号、商户密钥、供应商交易号或请求凭证。
- 原订单支付、查询、取消和退款操作继续绑定原编号；服务关闭支付时，现金操作按钮不可用，完整记录仍可读取。
- 旧服务无完整记录接口时明确显示最近记录，取消导出入口。钱包快照保留最近 100 条，并增加订单/退款总数。
- 复用现有紧凑行、下拉、按钮和滚动区。英文页签在窄屏换行；补齐退款词条和语言切换后的导出反馈。

## 只读接口和边界

| 路由 | 内容 |
| --- | --- |
| `GET /v1/payments/history/orders` | 当前账号的完整订单分页 |
| `GET /v1/payments/history/refunds` | 当前账号的完整退款分页 |
| 上述路由加 `/export.csv` | 所选时间范围的完整 CSV |

沿用服务端鉴权和持久 HMAC 游标，拒绝换账号、类型、日期、篡改、重复参数及客户端 owner。开始时间包含、结束时间不包含。游标排除首次查询后插入的新记录，时间相同按唯一编号排序，重启可继续；每页显示当前状态，**不是跨页冻结状态快照**。现金状态不作为分页筛选，避免处理中状态变化使记录漏页。

CSV 则持有独立只读 WAL 快照，不阻断账本写入。最大 100,000 条/64 MiB；单元格做公式与分隔符转义。原生固定路由、流式临时文件、长度和 SHA-256 核验完成后才替换目标文件，异常保留旧文件。

这提供账号内记录，**不等于商户账单核对或运营资金对账系统**。正式价格、订阅权益、退款规则、外部沙箱/真实资金、跨产品预算和正式路由发布仍有原来的待办边界。
