# Google Earth 历史影像接入 GeoD Agent

状态：已于 2026-10-27 随 GeoD Agent 0.2.13 正式发布，真实模型、本机下载、更新器及公开分发核验通过。发布未修改模型网关代码、额度或账本规则。旧 GeoD 仓库作为源码参考读取，没有为 Agent 修改旧产品或其发布流程。

## 实现

- 新增版本化内部包 `geod-earth-history` 0.1.0。复用旧 GeoD 当前采用的 Keyhole 目录、数据解码和投影采样实现；`UPSTREAM.json` 保留源码与副本摘要，包含工作区未提交源码的明确来源说明，不建立跨仓路径依赖。
- Source Creator 增加 `google_history_dates`、`google_history_source`；图源预设合同和技能增加 Google 历史入口，与 Esri Wayback 分开。查询日期、固定版本之后走既有图源登记、计划、批准、本机后台下载、裁剪、导出和核验。
- 目录根和截止日期构成不可变快照；每张输出瓦片的原生块选择在取图前持久化，恢复时复用。图源登记 ID 可以使用正常别名，显式 WGS84 与默认 WGS84 等效，版本绑定仍由完整快照 URI 校验。
- 历史服务网络连接复用现有自动/直连/手动代理设置。原生 URI 在代理决策中映射为实际 Google HTTPS 目标；真实任务日志记录了自动模式下使用 Windows 系统代理，启动和恢复的目标均为 `khmdb.google.com`。
- 缺少原生覆盖的输出瓦片交给现有缺失瓦片机制。有其他成功瓦片时可生成标注 partial 的成果；全部缺失返回 `SOURCE_TIME_UNAVAILABLE`，不发布空产物。历史记录不可读和协议不支持也有明确的恢复说明。
- 成果附带 `google-earth-history-*.json`，保留截止日期、逐块历史目录日期、版本、提供方署名和内容摘要。拍摄日期未核实的字段为 `null`。此能力下载的是处理后的地图影像，不冒充多光谱原始场景产品。
- 实跑发现任务详情仍显示裁剪前的瓦片网格尺寸，现优先显示已核验分析成果的真实尺寸；尚无成果时明确标为“瓦片网格尺寸”。新增工具进度、错误反馈及尺寸标签沿用现有界面与中英文文案。

Google 的[图像日期说明](https://support.google.com/earth/answer/6327779?hl=en)同样区分历史截止时间和组合图像的拍摄日期。查询点位有目录记录不能证明全区同日拍摄，实际覆盖以下载结果与元数据为准。

## 真实任务验收

隔离测试网关使用真实 DeepSeek Flash，账本为 `local-desktop-test`。没有伪造模型或工具结果；逐次确认模式保留，测试程序按明确授权的小范围，通过正常批准和启动接口批准一次任务，没有修改应用权限模式。

使用独立 TIFF 读取器核对尺寸、RGBA 模式与 GeoTIFF EPSG 键；按实际投影和像素大小定位，将 3 个成果像素与原生历史预览瓦片逐值回读比较，全部一致。界面截图确认实际地图叠加和 467 × 609 的成果尺寸，构建或单元测试本身不算像素验收。

另以真实目录根创建截至 `1800-12-31` 的同区任务，使用自定义登记 ID 与显式 WGS84，验证登记与原生下载全链路。结果为 `failed / SOURCE_TIME_UNAVAILABLE`，没有发布输出目录，没有额外模型调用；这是一项预期的无覆盖测试，不计作正常历史任务下载失败。

首次实跑暴露的 WGS84 校验误拒记录保存在 `registration-validation-failure.json`，该轮已停止，不能算成功验收。修复登记默认值和身份边界后，再单独进行上述干净实跑。开发端口最初被旧 GeoD 占用，也已隔离到 1466；按配置将 Agent 自己的历史记录合并复制至新开发来源，原来源保持不变，未清空旧会话。
