# Credits 完整用量记录：开发版验收

## 本轮范围

0.2.1 已发布的新用户赠送和正式网关结算保持其已发布状态。本轮继续补齐用量记录，改动在本地源码及开发界面验证，尚未替换 GitHub Release 产物或正式网关。

入口：账号与设置 → 余额与订阅 → AI 用量。

- 已结算与预留中分开查看，每页 20 条，支持前后翻页。
- 支持全部时间、最近 7 / 30 / 90 天。
- CSV 导出当前筛选范围的全部记录，包含精确 Credits、输入/缓存/输出/推理 token、原计费版本及请求编号；时间列明确为 UTC。
- 明细默认收起；沿用现有 LibreChat 风格、选择控件、滚动区域和深浅色主题。
- 旧服务没有完整记录能力时继续显示其真实的最近记录，不把窗口当作全部历史。
- 本机不限额模式没有钱包扣费记录。下载、数据处理及 BYOK 不加入托管模型账单。

## 服务与持久化

新增 `services/geod-agent-model-gateway/credit-history.mjs`，从既有 Credits SQLite 账本读取，不创建新收费或重复赠送：

| GET 路由 | 内容 |
| --- | --- |
| `/v1/payments/history/usage` | 已结算用量分页 |
| `/v1/payments/history/reservations` | 当前未结算预留分页 |
| 上述路由加 `/export.csv` | 当前时间筛选范围的完整 CSV |

`/v1/payments/status` 返回 `creditHistoryEnabled`。查询只接受 `from`（包含）、`to`（不包含）、`limit`、`cursor`；导出只接受时间参数。账号由 GeoD 身份验证确定，不接受请求中的账号、金额或 token 用量。

游标签名密钥持久保存在原账本，绑定账号、类别和时间筛选，并固定首次查询时的最大 rowid。相同时间记录通过请求编号稳定排序；翻页期间新增记录不挤漏原记录，网关重启后游标仍有效。预留中的记录会随真实结算或释放变化，因此其列表并非冻结的历史快照。

CSV 使用独立只读 WAL 快照，不阻断模型写账；支持按块发送及网络背压，关闭/中断会释放读连接。超过 100,000 条或 64 MiB 时明确要求缩小时间范围。所有单元格转义逗号、引号、换行及电子表格公式，金额用整数换算，避免浮点四舍五入。

桌面原生桥接只访问固定 GET 路由。导出在用户选定的目录创建临时文件，流式读取并核对长度和服务端 SHA-256，完整同步后才替换目标 CSV；响应类型不符、摘要错误或传输失败均保留原文件。

上述首次界面验收使用浏览器中的原生调用适配器，CSV 原生保存单独通过 Rust HTTP 测试。之后已补齐以下实际桌面和 Linux 归档验收。

### 实际桌面端到端验收

使用正常本地权限和打包前端的 release Rust 程序；仅将应用标识改为 `dev.geod-agent.credit-history-qa`，隔离 Roaming / Local AppData、系统凭据及独立后台。原开发程序和后台保留运行，没有切换现有用户配置或安装程序。

- **9 项实际核对通过**：真实 WebView → Rust IPC → 本机网关 HTTP → SQLite。没有注入或替换原生调用。
- 137 条记录真实分页，每页 20 条，前后翻页无重复；最近 30 天筛选为 136 条，费用预留单独显示。
- 实际点击「导出 CSV」，操作此验收程序的 Windows 保存窗口并读回文件；136 条筛选记录全部写入 CSV。原生直接保存也核验了中文文件名、完整长度及 SHA-256。
- 真实 HTTP 响应注入错误摘要后，原生接口返回核验错误，原 CSV 保持一致。
- 关闭并重开独立前台、重启隔离网关后，系统登录、签名游标、钱包和同一后台进程保留；重启后的导出通过。
- 真实 404 经原生错误转换后，界面回退至实际最近 100 条记录。
- 原有 **31 个会话**内容摘要、当前对话、钱包、前台/后台 PID 及登录启动设置核对一致；没有调用真实模型、赠送真实账号额度或发起现金支付。

验收中，最初配置的远程开发网页被原生 ACL 拒绝；最终改为程序打包前端，并保持默认权限。这是隔离验收配置的修正，没有放宽正式程序的远程权限。

可复验脚本：`apps/geod-agent-desktop/test/credit-history-native.mjs` 和对应 Windows 支持脚本。运行前必须构建包含独立 QA 标识的程序；脚本验证二进制标识，并按程序路径、PID 和创建时间处理自身进程，拒绝启动正式标识的程序。测试系统凭据仅使用随机本机身份地址，结束时移除。

桌面回执、CSV、截图、独立验收程序和构建配置保存在忽略目录 `artifacts/credit-history-native-20261004/`；首次浏览器及 Rust 测试证据仍保存在 `artifacts/credit-history-20261004/`。这些程序与账本是隔离验收产物，不是替换已发布安装包的发行版。

## 下一次发布需要的配置

正式反向代理当前只开放原有支付状态/产品/钱包 GET 路由。发布新网关时需一并允许上述四条 GET 记录/CSV 路由，并保持其他现金支付路由关闭；仅更新客户端不会开启完整记录。

本机已完成归档依赖和实际桌面 IPC/保存验收。下一次发行仍需打包具有新版本号的普通桌面安装包，并同步发布正式只读路由。示例代理配置应复用当前网关上游，严格匹配 `/v1/payments/history/(usage|reservations)(/export.csv)?`，仅允许 GET，保留身份校验与 `no-store`；不要扩大为整个 `/v1/payments/` 路径。发布前确认流式 CSV 的长度/摘要头在反向代理后仍完整，旧客户端及仅更新客户端的回退保持可用。

历史 `docs/implementation/candidates/payment-history/` 是 0.2.0 未验收草稿，本轮实现以服务目录及上述测试为准。
