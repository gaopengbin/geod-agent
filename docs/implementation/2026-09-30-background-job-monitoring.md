# 下载监控转入后台

## 原因与执行边界

下载已由本机 worker 执行，但模型在工具循环里反复调用 jobs_get/jobs_events，持续追加进度说明，占用对话区并消耗模型请求。启动任务后无需模型轮询至完成。

## 实现

- jobs_start 成功，或状态查询返回运行中的作业后，桌面端直接结束该轮模型处理、提交本机对话记录并释放输入框，不再发起下一轮模型轮询。
- 模型工具结果和每轮上下文都说明监控由 desktop-background 完成。用户主动再次查询任务仍可读取一次真实状态；完成后的成果查询仍可执行。
- 对话只保留一个稳定 jobId 的可展开状态行，默认 36px 高。原位更新状态、百分比；展开显示瓦片进度和任务入口。单条任务不追加进度消息。
- createBackgroundMonitor 直接读取 native jobs_get / jobs_events，增量事件 seq、防重入和取消订阅。瓦片检查点只用于进度，不进入日志列表。已完成/部分完成/已取消的任务停止轮询；失败/暂停仍可发现恢复操作。
- 账号的所有已保存会话中的任务均由同一个前端监控 hook 跟踪。切换会话只改变可见对话，不取消 worker；再次打开会话/应用读取实际本机状态。关闭本机应用后 worker 的运行生命周期仍遵循现有实现，本次不新增常驻 OS 服务。
- 完成、部分完成、失败、取消的状态转换通知一次，通知 8 秒后自动收起，也可手动关闭。初次读取已有终态不重复通知。
- 初次同步失败可见“状态同步中断”；后续失败保留已知进度并重试，不将读取失败解释为下载失败。
- 旧会话中连续的 jobs_get/jobs_events 和对应过程说明折叠为历史记录，不删除已保存对话，不吞掉用户消息、最终答复或其他操作。
