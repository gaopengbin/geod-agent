# 加密文档输入与实际验收

日期：2026-10-04。使用开发模式；本轮没有安装应用、发布网关或开启收费。之后的新增能力尚未进入先前生成的 0.2.0 安装候选。

## 使用方式

用户选择 PDF 或 Office 文件。需要打开密码时，界面显示文件名和本机密码表单；正确密码继续导入，错误密码清空后重试。Enter 提交，Escape 或取消结束剩余批次；切换会话时取消原会话尚未完成的请求。

密码只通过本机解析进程的输入管道传递，不写入命令行、环境变量、附件元数据、会话记录或模型提示词。原始加密文件与提取文本分别保存并校验 SHA-256；界面明确说明提取文字会保存，发送附件后提供给所选 AI。后台任务、会话分支和完整备份使用已保存文本，无需再次获得密码。

## 已验收的格式

| 格式 | 当前实际覆盖 |
| --- | --- |
| PDF | RC4 40/128 位、AES 128 位、AES 256 位 R5/R6；Unicode 打开密码、空用户密码和加密扫描页。 |
| DOCX / XLSX / PPTX | ECMA-376 Standard 和 Agile；正文、表格缓存值、幻灯片与备注保留既有提取规则。 |
| Agile 扩展 | AES-192 / SHA-384、AES-256 / SHA-512、AES-256 / SHA-1，空密码及完整性损坏。 |
| DOC / XLS / PPT | Apache POI 读取常见二进制 Office 文件的打开密码。 |

Agile 当前支持 AES-CBC。CFB 等未接入模式返回“加密方式暂不支持”；密码验证通过后完整性校验失败返回内容损坏，不要求用户反复输入密码。其他未验收密码算法、数字证书解密、企业信息权限管理不计为已支持。PDF 的原有识别、OCR 和读取容量仍适用。

## 运行时与修复

- 使用固定官方 PyPI wheel：pypdf 6.19.0、msoffcrypto-tool 6.0.0、cryptography 50.0.2、cffi 2.1.1、pycparser 3.0、olefile 0.47。Windows cffi 匹配应用自带 CPython 3.13；完整许可证随包保存。
- 使用带原始及修改后 SHA-256 的版本化补丁，修复 Agile 密码验证与 HMAC 的填充比较、密钥长度补齐和空密码处理。保留密码验证及数据完整性检查，解密后的 Open XML 包只在内存中解析。
- DOC / XLS / PPT 使用独立 Java 运行时，修复加密 PPT 异常分类；每次读取后清除 POI 的线程本地密码。
- 实际桌面验证发现开发模式曾优先载入旧构建目录的解析库。现在文档及旧版 Office 的开发模式优先使用当前准备资源，并验证完整固定清单；安装模式仍使用随包资源。
- 原生失败和取消不留半成品附件。密码请求是当前会话临时状态，持久会话快照不包含请求或密码。

补丁依据：[Microsoft Agile 密钥派生](https://learn.microsoft.com/en-us/openspecs/office_file_formats/ms-offcrypto/a57cb947-554f-4e5e-b150-3f2978225e92)、[完整性校验](https://learn.microsoft.com/en-us/openspecs/office_file_formats/ms-offcrypto/63d9c262-82b9-4fa3-a06d-d087b93e3b00)和 [Apache POI 加密支持](https://poi.apache.org/encryption.html)。
