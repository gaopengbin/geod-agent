# 大段坐标在本机处理

## 根因与实现

旧实现将完整 MCP 结果保存后每次向模型发送 7000 字符，模型通过 `mcp_result_read` 继续读页。完整路线虽然保存在设备上，模型仍然收到坐标并可能在思考中重复输出。

现在原始数据与模型摘要分别处理：

1. 原始 MCP 结果保留在受账号约束的本机调用记录中，新记录同时保存 conversationId。完整结果上限为 8 MiB，超过上限或旧版已截断记录明确报错，不能伪装完整。
2. `extensions/bulk_data.rs` 识别 GeoJSON coordinates、positions、分号/空格分隔坐标，以及长编码 polyline。累计至少 64 个点，或长编码 polyline 时返回 `bulkData` 摘要。可解析 MCP content[].text 中的 JSON。
3. 摘要保留可用的路程、时间、名称、错误状态等元数据，给出具体 JSON Pointer、点数、原始坐标单位中的包围范围、校验值。复杂结果明确标记样例/元数据范围，不把摘要称为完整阅读或可直接执行的几何。
4. `mcp_result_export` 从当前账号、当前会话的原始调用记录导出整个 JSON 或选定字段。返回相对文件路径、字节数、SHA256；无需再次请求供应商，也不向模型返回坐标。
5. 导出使用当前工作区 Full Access，检查链接/Windows 重解析目录，不覆盖改变过的文件。重复导出完整相同文件复用。坐标和精度原样保存，不简化、不推断 CRS、不做隐式转换。
6. Codex 前台与后台工具都接入原始文件导出。统一模型指令要求本机工具/脚本处理该文件，仅打印摘要、统计及文件路径。
7. 旧坐标分页在 Responses 请求、兼容模型合同以及新引擎导入会话时，发送给模型前转换为原始本机记录引用。原始 UI 历史和调用记录保持不变；不修改供应商签名或 opaque provider state。
8. 工具记录显示“完整坐标保存在本机”，不显示为继续逐页读取。

## 验证

- 原生函数：7 个 bulk 测试，另 1 个旧记录兼容测试通过。验证原始所有点/高程保留、内嵌 JSON 指针、分号 polyline、短数据不改动、很多小段、错误标志、落盘、重复复用、禁止覆盖、账号/会话隔离和重开记录。
- 现有 MCP 相关回归：21 个通过，6 个需要外部服务的用例按其原有标记跳过；非几何大文本仍能完整分页还原。
- JS：几何旧页、导入历史、函数/自定义工具 output、调用配对、签名及工具定义同步等验证通过。
- 真实固定版本 Codex 引擎 + 可重复的供应商和原生函数产出 fixture：完成 MCP 摘要 → 原始文件导出 → 最终结果的 3 轮流程。模型请求里没有完整坐标，未调用付费模型。1000 个点的文件校验值和本机计算的包围范围均匹配原始记录。
- 上述 fixture 原始内容 15987 字符、摘要 1030 字符，文本减少 93.6%。这是输入文本规模，不是实际 token 或总费用比例。
- 网关 11 个回归与模型适配器 14 个回归通过，确认实际用量、调用配对、签名和结算合同不变。
- 前端构建与原生开发构建通过，保留原有大分块提示与一项 sql_tls 未使用函数提示。
- 重启后的真实桌面，读取当前会话两个已存路线结果：原始 20701/15065 字节，摘要 2277/2273 字符，分别包含 190/132 个点的字段引用。原历史不变，没有付费模型请求、地图供应商请求或工作区写入；Confirm Each 下原始文件导出明确返回 MCP_APPROVAL_REQUIRED，新命令和权限检查均有效。

主要证据在 `artifacts/bulk-data-20261007/`：`native-fixture.json`、实际导出的 `geod-local-data/*.json`、`core-report.json`、当前桌面 `desktop-report.json`。

## 边界

本改动对保存在本机的外部 MCP 几何结果和旧坐标分页生效。其他非几何结果继续原分页逻辑；模型的思考仍由供应商生成，指令不能保证所有模型永远不会输出冗长文字。供应商 token 用量依旧按实际回执记录，不因摘要或折叠而改写账单。

已更新本机开发环境；未发布安装包或部署线上服务。既有用户任务不自动恢复、下载或重新请求供应商。
