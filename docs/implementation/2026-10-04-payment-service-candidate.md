# GeoD 独立支付服务候选

本轮将支付候选接入了可选网关宿主、原生接口和「余额与订阅」界面，继续补齐用量明细与请求费率快照。实际验收使用本机协议服务和临时生成的 RSA 密钥，模型输出也是明确标注的协议样本。没有读取真实商户私钥、创建真实支付或退款、发布服务或改变原来运行中的测试网关。

2026-10-05 更新：下文保留现金支付候选的分阶段结果；Credits 用量及费用预留的完整分页、时间筛选和 CSV 已整合进本地 0.2.2 普通发行候选，尚未发布。后续独立候选分支补齐订单/退款完整分页、筛选和导出，见 `2026-10-05-payment-history.md`；本轮未重新整合普通安装包。正式只读路由仍未更新，真实资金和商户对账仍需独立验收。

## 已实现

| 部分 | 本轮实现 |
| --- | --- |
| 支付宝适配器 | 官方 `alipay-sdk` 4.14.0，电脑网站支付 V2、RSA2 通知验签、签名查询、关闭、整笔未消费余额退款及原退款查询。SDK 兼容 V2 的 `exec` 接口仍用于现有产品协议；不是已经迁移 V3。 |
| 订单 | `GDA` 独立订单前缀、GeoD 账号归属、请求幂等、服务端商品快照、精确分金额及已配置的单笔/本产品每日预算。客户端不能提供价格、余额或收款方。 |
| 到账 | 通知和主动查询都先核对签名、应用、收款方、订单、金额及交易号，再在 SQLite 即时事务内发放一次余额/订阅。返回页和打开收银台不算支付。 |
| 模型余额 | 由宿主提供可信网关读取函数，先保留服务端计算的最高费用，再按已结算的实际用量以整数 nano-CNY 扣费。缺缓存用量、待对账、超预留金额均不推算扣费；确认失败释放预留。赞助和个人渠道不扣本钱包。 |
| 资金退款 | 候选仅支持整笔完全未消费的充值余额：先冻结、固定 `GDRF` 请求号，再请求退款。未知结果或进程中断后继续查询同一退款；已确认结果才销账。SDK 自身网络重试也复用这个编号。 |
| 失败任务退费 | 客户端提交的下载失败不能作为服务器可信事实；只建立人工核对申请，不自动增加余额。旧本机模拟候选的自动失败退款规则没有冒充正式服务证明。 |
| HTTP | 注入 GeoD 专属鉴权；订单/余额/查询/取消/退款按账号隔离。通知只接受受限长度的表单，并拒绝重复字段。没有公开修改用量、直接发钱或设置账号的接口。 |
| 网关宿主 | `server.mjs` 已接可选 `GEOD_AGENT_PAYMENT_CONFIG`，默认关闭。可信生成记录由服务端账本直接读取，模型请求前预留费用，实际结算/重复读取不会重复扣费。测试网关不扣钱包，赞助渠道仍独立记账。 |
| 请求费率 | 请求开始时保存版本、模型及整数费率快照；重启/调价后按原版本结算。同一版本不能修改费率。迁移前缺少快照的未结算请求进入核对，失败请求仍可释放预留；不猜测旧价格。 |
| 原生付款 | 只接入创建、打开收银台、查询、取消和退款五种账号内操作。由原生层校验支付宝收银台环境/来源，再交给系统浏览器；客户端不能提交支付金额或自行写入到账。 |
| 余额界面 | 账号菜单内独立对话框，包含余额与方案、支付记录、AI 用量三个页签。紧凑订单行和可展开的费用明细；中文/英文、明暗主题、窄窗口、键盘页签及关闭焦点已有实际界面验收。 |
| 用量查询 | 余额分别显示可用、请求预留及退款冻结金额。扣费行列出精确金额、输入/缓存/输出 token、原费率及版本；预留行独立显示。原钱包快照保留最近 100 条及总数作为旧服务回退；后续 Credits 完整记录另接签名游标分页、时间筛选和 CSV，不包含对话内容、上游凭证或内部供应商成本。现金订单/退款快照仍为最近 100 条。 |

数据库绑定产品、应用、收款方及环境。测试账本不能换成真实商户后继续作为资金账本使用。

## 当前商品草案

延续已有收费草案，尚未作为正式售价确认或销售：

- 10 元/20 元 AI 余额候选。
- 29 元、30 天订阅候选，包含 10 元 AI 余额。
- 本地执行仍不单独计价。

模型计算沿用 `pricing-candidate.mjs` 的固定候选费率和版本，供应商成本标记为估算，当前仅对 DeepSeek Flash 提供此候选费率。正式价格、余额有效期、月订阅权益及订阅/部分消费退款规则仍待确认；不能把商品草案当作已经销售的套餐。

仅增加商户配置不能自动售卖。外部环境还要求明确的 `catalogueApproved`、匹配的 `approvedPricingVersion` 和商品指纹 `approvedCatalogueSha256`；商品或价格变化后旧批准不能继续套用。配置字段本身不等于取得上线或真实资金操作授权。

## 实际验收

`artifacts/product-gaps-20261004/payments/acceptance.json`：62 项网关检查通过，其中支付协议 14 项、网关宿主 5 项；完整 TAP 日志与依赖审计已保留。

支付测试实际运行官方 SDK，并以临时生成的商户/提供方 RSA 密钥连接本机 HTTP 服务：

1. 精确金额、重复通知字段拒绝。
2. 未显式启用时真实网关请求被拒绝，本机模拟地址不能指向公网。
3. 真实 SDK 签名收银台链接、回调/查询并发、幂等与账本重开。
4. 签名正确但应用、收款方、金额或交易归属错误仍拒绝；错误响应签名不能到账。
5. 迟到支付保留为待核对；不明确的关闭结果仍保留原订单。
6. 服务端实际用量输入的精确扣费、并发幂等、未知缓存和非可信客户端失败申请。
7. 原子预留防止透支，确认的提供方失败释放额度，赞助渠道跳过本钱包。
8. 退款响应丢失后保留冻结金额，重开账本查询原请求，不重复退款。
9. 已使用的余额和订阅不能冒充未使用充值进行退款；商户/环境改变不能复用原账本。
10. 跨日仍不丢掉不明确的待付款占用；现金退款不回补同一天支付预算。
11. 超过原费用预留时不进行部分扣费。
12. 单独 Node 账本进程实际被终止并重新创建：冻结退款、模型预留及原请求编号保持；签名查询确认后再结算。
13. 请求保存原费率后重启并切换新版本：旧请求费用仍为 `0.01024` 元，新请求按新费率计价；历史、指纹及账号归属正确，同名版本改价被拒绝。
14. 实际旧表迁移：没有价格快照的已完成请求保留为核对，确认失败释放预留。冻结余额和预留分别保持，原退款查询确认后解除冻结。

五项宿主检查覆盖默认关闭、模型请求前拦截、可信用量扣费与重放、缺用量/流中断保留、明确失败释放、观察模式不扣测试余额、商品批准及模型/数据库边界。

### 原生窗口与恢复

`artifacts/product-gaps-20261004/payments/native-ui` 中分阶段记录：

- `initial-acceptance.json`：实际账号入口、原生钱包、方案预览及同一待支付订单的关闭/重开。
- `restarted-acceptance.json`：桌面真实重启后保留订单；签名样本通知到账一次；丢失退款响应后固定原请求，重开账本查询同一退款。
- `settlement-acceptance.json`：前台与后台进程真实退出/重建后保留另一订单；原生生成接口结算可信协议用量；已消费余额不能误报退款成功。
- `visual-pass/visual-acceptance.json`：共享滚动区、窄窗口、页签键盘操作和关闭后的焦点恢复。
- `usage-pass/usage-acceptance.json`：原生接口的一笔 `0.01024` 元样本费用、一笔缺缓存用量的费用预留及一笔未确定退款的冻结金额，三者分开保留。四种语言/主题组合、390px 窄窗口、完整滚动读取费率和版本均通过，英文界面无中文状态残留。
- `retry-pass/retry-acceptance.json`：不明确的取消通过原生接口及签名样本服务核对；再次购买同一方案不会替换或重复下单。另实际创建并关闭 101 笔样本订单，已完成的旧请求超出最近 100 条记录后，先由服务器确认完成，再只创建一笔明确的新购买；打开收银台未增加余额。
- `retry-pass/restore-acceptance.json`：最后恢复原网关后，语言、主题和下单请求存储与验收前完全一致；实际模型入口仍不限额。之前的 `usage-pass` 恢复记录也通过。

上述七组已通过记录合计 19 项原生/界面检查；早期 `native-ui/visual-acceptance.json` 的验证脚本失败保留为排查记录，不能作为通过证据，最终视觉验收以 `visual-pass` 和 `usage-pass` 为准。

演练服务已停止，开发前台与后台重新连接原 `43123` 网关。30 个会话原文哈希、当前会话及四个连接 ID 一致；`original-profile-preserved.json` 留存结果。既有模型网关 PID/创建时间保持。没有将样本订单或协议模型输出写进聊天历史。

`desktop-candidate-acceptance.json` 汇总最终源码指纹、前端构建、原生接口测试、各阶段记录及恢复状态。付款和退款仍为本机样本，未完成支付宝外部沙箱、真实商户资金或线上回调验收。

### 后续 Credits 完整用量记录

`artifacts/credit-history-native-20261004/native-acceptance.json` 与 `continuation-acceptance.json` 已核对：9 项实际 WebView → Rust IPC → HTTP → SQLite 验收通过；137 条用量每页 20 条，时间筛选后的 136 条通过 Windows 保存窗口全部导出，错误摘要保留原 CSV，重启及真实 404 旧服务回退通过。Linux 全套 81 项与归档的四条只读记录/CSV 路由通过。没有真实模型收费、现金支付或正式服务修改。

实现位于 `credit-history.mjs`、`src/credit-usage-history.tsx` 和 `src-tauri/src/services/credit_history.rs`。这些 GET 路由只查询当前账号的 Credits 用量与预留，不是现金购买、退款或订阅的完整运营对账入口。详情见 [完整用量记录](2026-10-04-credit-history.md)；普通 0.2.2 安装包、免安装 ZIP 及 Linux 网关的后续构建核对见 [0.2.2 可审阅候选](2026-10-05-release-candidate-022.md)。

## 接入位置

- `alipay-payment-candidate.mjs`：适配器及显式环境/网络配置。

客户端位置：`src/payment-dialog.tsx`、`src/payment-dialog.css`、`src/api.ts`；原生位置：`src-tauri/src/services.rs`。现金支付候选采用上述开发模式验收；之后完整 Credits 用量已生成普通 0.2.2 发行候选。没有通过本轮验收重新安装应用或启用现金支付。
