# 模型请求同步当前任务状态

## 问题

用户在任务面板确认并完成 13 个历史影像下载后，后续图源配置回复仍沿用历史对话中的“等待确认”。右侧面板刷新了任务状态，模型请求没有获得这次本机状态更新。

## 修改

- 在原生模型传输边界，每次实际模型请求前只读刷新当前账号、当前会话的影像任务账本。覆盖 Codex 托管、个人渠道、赞助渠道以及旧引擎的普通/流式请求。独立文件分析子任务不注入 GIS 状态。
- 使用单次 SQLite 查询读取已绑定计划和最新任务，后台写入完成后下一次请求即可读取；不依赖 React 渲染闭包或有数量上限的任务列表。
- 区分已批准但未启动、未启动、排队、下载、暂停、处理、核验、完成、部分完成、失败及取消。未启动不自动解释为等待确认；完成不解释为待确认。部分完成不能汇总成全部完成。
- 总数和各状态数量覆盖查询范围内全部计划，明细最多 32 项。缺失数据/查询失败返回不可用，不伪装成零任务。只提供标识、状态、数量及读取时间，不向模型加入路径、坐标或完整计划。
- 新快照替换旧快照，保留原有模型指令、工具合同、工具调用配对及历史聊天；账号切换时拒绝旧 Codex 运行继续请求。没有改变原生审批、启动或文件检查规则。

## 验证

- 原生测试 `task_state_context::tests`：4 项通过。
- 临时真实账本创建计划、批准和启动任务，模拟独立后台写入最终状态：13 项从排队变为完成后，新请求包含 `completed:13`，旧 `queued:13` 快照被替换。
- 覆盖账号/会话隔离，完成/部分完成/失败/取消/暂停/核验区分，40 项总数与 32 项明细限制，只读失败不创建数据库，消息历史与工具配对保持完整。
- 开发版原生构建成功。测试使用本机临时账本模拟后台状态写入，没有调用收费模型或重新执行用户下载。

本次修改用于开发版，尚未打包发布；历史聊天文字保持原样，后续模型请求获得最新事实。
