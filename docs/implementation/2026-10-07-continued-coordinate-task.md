# 输出超限后的坐标任务续接

## 实际问题

原会话 `0b3f3b0a-19ca-4fe9-a70a-ae1524f6864e` 的需求是下载沿途 1 公里范围影像。用户已在问答卡提交图源、分辨率、坐标系三个选择，之后明确继续任务。

本次原生回执 `c1e0f803-7064-490c-b605-978ebb7f1cf2` 为 failed；最后一次 DeepSeek Flash 生成实际输入 74,680 token，输出 8,192 token，finishReason=length。供应商返回 24,449 字符思考、0 字符正文、0 个工具调用，思考里有 307 对坐标，仍在手工拼接路线。以上来自供应商已结算回执，不由屏幕状态推断。旧回执查询失败时保留原证据，不能仅凭 token 数补造 finishReason。

遗漏在内嵌地图通道：外部 MCP 已有本机几何结果引用，但 OpenLayers exportFeatures 的 GeoJSON 仍直接进入模型；旧会话也保留该内联结果。

## 修改

- OpenLayers/Cesium 内嵌地图产生大段几何时，先通过 `mcp_embedded_result_save` 保存完整原始 JSON，再返回点数、范围、校验值、executionId 和 JSON Pointer。保存受当前账号及会话约束；相同调用可复用，改变原数据或跨账号/会话不能覆盖。
- Codex 模型请求和新线程导入旧会话时，检测真实 mcp_call 与对应 output 中的旧内嵌几何。在本机缓存成功后才生成引用，仅替换模型请求副本中的工具结果；保存的原始消息、地图、工具参数和原生线程保持不变。普通结果、已有引用和短几何照旧。
- 延续原来的 `mcp_result_export`：完整数据原样落盘供本机 GIS 工具处理，不抄坐标、不删点、不改精度、不猜坐标系。写入用户工作区仍要求原有 Full Access；Confirm Each 返回明确权限错误。
- 显式“继续处理”附上同一任务的原始请求和真实已提交答案；不复用取消/未答/秘密输入，不把一次选择写成会话默认，不影响新任务。提醒检查已有计划和下载状态，避免重复创建。
- 输出超限等已结算失败由持久化“本轮未完成”卡报告，不再同时重复顶栏错误。历史两次失败仍分别保留；仅用户继续才新建模型请求。

DeepSeek 官方要求工具模式完整回放已有 reasoning_content，包括无工具调用的轮次。因此没有通过删改思考、签名、opaque provider state 来缩减请求，也未改模型、思考档位、输出上限或自动重试策略。参考：https://api-docs.deepseek.com/guides/thinking_mode/
