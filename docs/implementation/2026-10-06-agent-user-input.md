# Agent 需求问答卡

## Scope

- Shared `ask_user` function is advertised to hosted and Codex/custom-provider routes. Questions and options are generated by the actual model; the application validates and displays them, then sends only the submitted answers back as tool results.
- 1–3 question tabs, descriptions, radio choices, custom text, back/next navigation, explicit submit and cancel. No option is accepted by default. Existing Codex `item/tool/requestUserInput` uses the same UI. Approval and MCP authentication cards retain their separate protocols.
- Foreground turns wait for the user. While waiting, later tools cannot execute. After an answer, pre-generated sibling tool calls are rejected until a fresh model round reads the result. Cancelling stops future actions in the current turn. Requests are scoped to conversation sessions and cancelled on account disconnection.
- The frontend adds a specific guard for recognized historical requests without an explicit year/date/period: planning and starting are blocked with `HISTORICAL_PERIOD_REQUIRED`. Model instructions cover additional ambiguous requirements. Natural language recognition is deliberately narrow; this is not a universal semantic verifier of every possible time expression.
- Background AI runs have no invented answers: `ask_user` returns `USER_INPUT_REQUIRED`; the existing scheduled runtime marks the occurrence as requiring user attention and interrupts execution.
- Wayback catalogue publication dates must not be described as local capture dates. Inspect `wayback_metadata` before making capture-year/season claims.
