# GeoD 数据源授权与下载接入方案

日期：2026-09-28。状态：实施方案；不代表这些平台已经完成授权联调或原始产品下载。

## 目标与用户路径

用户在 GeoD 中选择数据平台，按平台支持的方式完成一次授权。GeoD 显示**当前账号实际可用的能力**，而不是仅显示“连接成功”。用户选择区域、时间、产品后，GeoD 检索候选数据、说明费用与限制、生成下载计划；用户确认计划后，GeoD 在本机下载并核验文件。GeoD Agent 以后调用同一套确定性接口，把自然语言需求转成检索与计划，不另建一套下载逻辑。

```text
选平台 → 授权/导入合法交付清单 → 测试能力 → 检索产品
→ 查看可下载权益与成本 → 确认计划 → 本机下载/恢复
→ 文件核验与来源记录 → Agent 引用成果
```

“一次授权”是产品体验，不是所有平台共用一个密钥。GeoD 账号标识用户和 Agent 用量；第三方凭证只授权对应平台及对应产品。平台提供 OAuth 时优先跳转官方授权页；提供 AK/token 时由用户在本机录入一次；采用账号、申请、订单分发的平台，在官方页面完成必要步骤后，由 GeoD 接收官方交付链接或下载清单。没有公开接口的平台，先提供申请引导和成果导入，不把网页 Cookie 抓取当成稳定接入。

## 用户看到的连接状态

| 状态 | 含义 | 可进行的操作 |
| --- | --- | --- |
| 未连接 | 尚无凭证，或该服务无需凭证 | 查看公开目录与平台说明 |
| 已连接·仅浏览 | 小范围真实请求通过，但当前凭证只验证了地图/预览 | 浏览与规划；不显示“可下载原始数据” |
| 已连接·可下载 | 指定产品的下载权益经接口或合法交付清单验证 | 对该产品生成下载计划 |
| 需平台操作 | 需要实名、申请、订单、付款或协议 | 打开官方入口；返回后刷新权益或导入清单 |
| 凭证失效 / 超额 | 401/403、额度耗尽或过期；保留原错误类别 | 更新授权、查看额度、稍后重试 |

每张数据源卡显示：提供方、数据类型、覆盖与更新时间来源、可执行动作、当前账号权益、限制与计费、测试时间。连接测试只请求一个最小样本或只读权益接口；HTTP 200、目录命中或得到瓦片都不能自动升级为“原始数据可下载”。

## 适配器合同

`ProviderAdapter` 由 GeoD 本地可信代码实现，并由版本化登记表声明能力。最小接口如下；没有能力的提供方返回 `unsupported`，而不是模拟成功。

| 操作 | 输入 → 输出 | 约束 |
| --- | --- | --- |
| `connect` | 平台授权流程 → 本机凭证引用 | 不把密钥放进 URL 模板、设置 JSON、模型上下文或日志 |
| `probe` | 凭证引用 → 已验证能力、额度、失效时间、测试时间 | 分别测试检索、预览、下载；不得以一种能力推断另一种 |
| `search` | 区域、时间、产品过滤 → 标准化候选产品 | 保留提供方 product/scene ID、分辨率、波段、云量和原始元数据出处；未知值不填造 |
| `entitlement` | 产品 ID → 可下载状态、费用、用途/再分发限制 | 权益以产品与账号为粒度；订单待审可返回 `action_required` |
| `plan` | 产品、范围、输出 → 文件/瓦片清单、大小估算、计划哈希 | 固定来源版本、凭证引用版本、产品 ID 与许可快照；展示费用和可能缺口 |
| `fetch` | 已批准计划 → 本机任务 ID | 限定官方域名与重定向；支持暂停、恢复、重试及来源限速 |
| `verify` | 文件/清单 → ArtifactManifest | 重新打开文件，检查 SHA-256、大小、格式、CRS、波段、足迹及缺失项 |

`DatasetAsset` 至少区分 `map_tile`、`rendered_preview`、`original_product`、`processed_product`。瓦片拼接得到的 GeoTIFF 仍标记为“地图服务导出”，不得冒充原始多光谱产品。HDF/NetCDF/ZIP 先验压缩包与内部清单，再按可用驱动检查科学数据；缺少空间参考或波段信息须如实标记。

下载引擎已有的计划、审批、幂等作业和 manifest 可沿用，但当前 `HttpSource` 仅支持无密钥 XYZ/TMS 或 ArcGIS ImageServer 地址，且拒绝 URL 查询参数；`SourceDescriptor.credential_ref_version` 只是预留字段。接入上述适配器前必须增加独立的凭证注入与服务类型合同，不能让用户把 token 粘进现有 URL 模板。凭证保存在系统凭据库；任务账本只记引用和版本。GeoD 与独立安装的 GeoD Agent 要复用同一连接，需实现稳定的本机连接 ID、版本化提供方合同与受控的同用户凭证访问；两个产品当前并未具备这种共享连接能力。GeoD 托管模型仅接收能力摘要、产品元数据和脱敏任务结果。首发下载继续在用户电脑执行，GeoD 服务端不接收第三方原始密钥或代传影像。

技术基线可以继续用已完整下载并检查的 Sentinel-2 COG 检验“原始资产下载与 GeoTIFF 检查”通路，但它不能作为国产卫星产品验收。上表第 2 项成功之前，产品不能宣称“已支持国产卫星原始产品一键下载”。

## Agent 接入方式

Agent 只使用 `providers.list → search → entitlement → plan → job.start → job.status → artifact.inspect` 这些有类型工具。模型可以建议平台、时间、云量、分辨率和产品，并指出某个候选需要用户去平台完成申请。模型不能读取密钥、伪造权益、替用户同意付费或从聊天文本推定下载完成。`job.start` 继续要求用户确认具体计划；相同计划重复调用返回同一任务。最终回复引用已核验的 manifest 和本机成果。

## 第一版交付判定

1. 用户不编辑 URL 模板即可完成一个 token/AK 平台连接；连接测试分别展示浏览与下载权限。
2. 至少一个国产原始产品通过**合法授权后的真实文件下载**，完成断点恢复、文件打开、元数据与 SHA-256 检查；仅有瓦片或 JPEG 预览不计。
3. 无权、过期、超额、订单待审、下载链接失效、文件损坏分别给出可操作结果；失败不生成“已完成”成果卡。
4. 同一用户在 GeoD 手动工作流与 GeoD Agent 中看到同一连接、同一产品权益和同一任务结果；Agent 不建立第二套来源权限。
