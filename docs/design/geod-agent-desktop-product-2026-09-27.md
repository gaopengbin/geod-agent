# GeoD Agent 桌面产品：调研与设计

日期：2026-09-27，模型方案更新于 2026-09-28。状态：产品设计快照；当前实现与剩余验收以[桌面与网关实施记录](../implementation/2026-09-28-desktop-and-gateway.md)为准。

实施层面的模块边界、任务合同、恢复、安全与发布门槛见[技术架构设计](geod-agent-desktop-technical-architecture.md)。

## 1. 产品决定

**GeoD Agent 是独立安装的地理数据获取与交付智能体。** 用户描述要取得什么数据，Agent 把需求转成可检查的计划，用户在地图上确认范围、来源和资源预算，电脑本地执行，最后交付可定位、可追溯、可复用的文件。聊天是任务入口，地图是事实校对区，任务与成果是最终价值。

它复用 GeoD 的下载和处理能力、图源及账号基础设施，但拥有独立的信息架构、任务状态和安装包。现有 GeoD 桌面版继续提供手动专业操作。该方案只针对国内 GeoD；独立的 GeoD Global 仓库和产品决策不随本方案改动。

**已确定的模型体验：GeoD Agent 使用 GeoD 托管模型。** 用户登录 GeoD 后可直接使用 Agent；模型密钥、供应商路由、额度与用量账单由 GeoD 服务端管理。既有 GeoD 桌面助手的自带 Key 设置不作为新产品的入门步骤。

一句对外介绍：**说出需要的区域和数据，GeoD Agent 在你的电脑上规划、获取、处理并交付。**

## 4. 服务对象与工作任务

1. **需要交付数据的 GIS/测绘人员**：知道目标区域和输出格式，想减少图源参数、裁剪、重试与成果检查的手工步骤。
2. **需要数据但不熟悉 GIS 工具的研究/开发人员**：会描述地点和用途，需要解释范围、级别、来源、文件大小与坐标系。
3. **已经有 GeoD 图源的团队用户**：希望沿用自己的合法授权图源，把一次任务变成可复用的任务模板和成果记录。

核心任务从 GeoD 已有内容收敛：图源选择/注册、范围定位与边界导入、影像及现有 GeoD 数据类型的获取、拼接/裁剪/离线打包、成果预览与核验。第一条完整生产链围绕**授权图源的影像下载**；DEM、OSM、历史影像、3D Tiles 等纳入产品蓝图，在各自适配器通过真实样本验收后开放。

本产品暂不承担通用网页/文件自动化、任意 GIS 空间分析、摄影测量三维重建、任意代码执行、GeoStyle 制图工作区。对不支持的请求，Agent 应明确指出当前能交付什么以及缺少什么。

## 5. 一条真实任务如何完成

示例输入：**“用我已授权的影像源，获取华盛顿城区一小块范围，12 级，导出 GeoTIFF 和离线瓦片包。”** 图源的许可与覆盖范围必须在本地校验；示例不暗示 GeoD 自带可下载高精度商业影像。

1. **理解**：从对话和用户提供的边界文件中抽出区域、图源、缩放级别、边界、输出格式。缺失字段由 Agent 简短追问；不可凭空捏造图源和边界。任务工作区不提供手动参数表单。
2. **规划**：Agent 调用只读本机工具，由确定性估算器计算瓦片数、流量、输出大小、内存/磁盘风险；地图预览范围、格网与实际裁剪边界，并显示来源署名与许可提醒。
3. **确认**：计划卡列出图源、范围、级别、文件格式、自动建议的本机输出目录和预计消耗。用户通过对话要求修改后重新生成计划；确认操作绑定最终版本的计划哈希。
4. **执行**：在本机下载、拼接、裁剪、输出。对话区同步解释进度，任务区显示瓦片成功/失败、当前步骤、暂停、恢复和取消。模型重试不得重复创建任务。
5. **验收**：本机重新打开成果，核对影像足迹、坐标系、透明裁剪、缺失瓦片、尺寸、文件哈希和来源。只有完成检查才标记“已交付”；缺瓦片用“部分完成”。
6. **交付**：展示预览、文件清单、输出目录和机器可读 manifest；支持一键打开目录、复用相同计划、生成可分享的任务说明（默认不上传影像文件）。

任务参数由 Agent 经对话和受限工具生成，地图用于核对，不作为手动任务设置入口。账号和图源授权保留单独的用户确认入口；计划批准、暂停和取消仍是用户明确动作。对话中的“我已经下载好了”必须以本地任务状态及成果检查为依据。

## 6. 信息架构与界面

### 工作区结构

早期[工作区示意图](geod-agent-desktop-wireframe.png)已归档；以下结构反映当前采用的 Agent 应用布局。地图及数字以运行时数据为准。

```text
┌───────────────────────────────────────────────────────────────────────────────┐
│ GeoD Agent                                                  主题  展开成果页 │
├───────────┬─────────────────────┬──────────────────────────┬──────────────────┤
│ 对话列表  │ Agent 对话           │ 地图与计划范围预览        │ 可展开成果页     │
│ 新对话    │ 用户目标与 Agent 补问 │ 待取区域 / 成果足迹       │ 计划与批准       │
│ 历史对话  │ 工具结果与执行解释   │ 影像与空间核验            │ 作业与进度       │
│ 本机保存  │ 输入框               │                          │ 文件与质量       │
└───────────┴─────────────────────┴──────────────────────────┴──────────────────┘
```

左侧保存和切换本机对话；对话与地图是主体。MapLibre 使用 OSM 在线底图、计划范围框和已核验本地影像图层，显示影像来源与 OSM 署名。图源授权由对话区独立入口完成，不在任务表单中配置。右侧成果页默认收起，生成计划或选择历史任务时展开，展示计划、进度和成果。窄窗口将地图移到对话下方，成果页作为覆盖面板展开。

### 视觉方向

- 用户选择 Vercel 方向的紧凑导航、清晰边界与技术产品层级，同时明确保留 GeoD 蓝白品牌，并要求亮暗主题。界面采用蓝白亮色与黑色暗色，蓝色仍用于品牌和关键操作；主题选择在本机持久化。
- 按 `laogao-shadcn-ui` 检查组件和交互。按钮使用已接入的 beUI 组件，授权图源弹窗和下拉采用 Radix 交互底层并适配 GeoD 颜色；图标使用 Lucide。
- 产品标志性的可视化是**任务覆盖层**：同一张地图上，规划时显示待取瓦片格网，执行时显示完成/缺失覆盖，交付时显示真实成果足迹和裁剪透明区。它编码任务事实，不作循环装饰。
- 动效只服务状态转变：计划卡展开、覆盖层由待取变完成、成果预览出现。提供 reduced motion；下载进度保持数值可读，避免仅用动画表示。

## 7. Agent 与本地执行架构

```text
GeoD Agent 桌面 UI（独立 Tauri 应用）
  ├─ 对话、地图、计划卡、任务中心、成果检查
  ├─ Agent Runtime：模型消息 ↔ 有类型工具 ↔ 工具结果 ↔ 最终答复
  ├─ Policy Gate：来源许可、等级/账号、资源预算、具体计划审批
  ├─ GeoD Task Engine：范围/图源/下载/拼接/裁剪/导出/检查/恢复
  └─ 本地任务与成果存储
       ├─ GeoD 账号：身份、可选图源同步、托管模型额度与账单
       ├─ GeoD 模型网关：鉴权、限额、路由、流式响应与用量核算
       └─ 图源服务：瓦片由用户电脑直接读取；GeoD 服务器不转发瓦片
```

本仓库承载独立的 `apps/geod-agent-desktop/` 和 `crates/geod-task-engine/`。旧仓库的 `src-tauri` 下载命令依赖应用状态和事件系统，不能直接跨仓引用；应先把纯下载/导出逻辑整理成有明确来源、许可和版本的 Rust 能力，再迁入本仓库的 `crates/geod-core/`。旧桌面与 CLI/MCP 是否采用同版本合同，由各自仓库通过发布版本和兼容测试推进；发行程序不得依赖开发机上的相邻目录。现有 `geod-core` 只能作为有界任务合同的参考，具体能力以适配测试证明。

模型请求经 GeoD 模型网关进入经验证的上游模型路由；用户客户端不持有供应商密钥。模型只收到完成任务所需的区域、来源标识和工具结果；图源 URL 中的密钥、完整本地路径、原始日志默认不进模型上下文。服务器承载身份与模型流量，本机承载瓦片下载及影像计算。模型具体供应商与默认额度在上线前经工具调用和成本验证确定。

参考逆向报告中的模型工具调用修复线索，模型适配层需把不完整、重复或失配的工具调用转为可诊断错误；恢复时先查本地任务账本，不能重新执行已批准的下载。该可靠性要求独立于具体模型提供商。

工具按域分组，全部接受有类型的输入并返回可检查的结果：

| 只读与草稿 | 需用户确认的本地操作 | 交付与核验 |
| --- | --- | --- |
| `list_sources`、`resolve_area`、`inspect_boundary`、`plan_download`、`estimate_resources` | `save_source`、`start_download`、`pause_job`、`resume_job`、`cancel_job`、`change_output` | `job_status`、`inspect_artifact`、`open_output`、`export_manifest` |

“选择图源”只传本地图源 ID；实际 URL 由任务引擎读取。`start_download` 必须带计划 ID、计划哈希、审批记录和幂等键。模型拿不到任意 shell、浏览器控制或任意路径读写工具。

状态机：`draft → needs_input → planned → awaiting_approval → queued → running → verifying → completed | partial | failed | cancelled`。任务状态持久化在本地，重启后根据下载引擎实际进度恢复；对话消息只是状态的说明，不是状态本身。

## 8. 安全、来源和费用边界

- 图源由用户选择或注册，并显示来源、许可、署名和下载限制。OSM 官方瓦片只作为交互底图读取当前视窗并按缓存政策保存，不能进入任务下载、批量预取或离线包；对把 OSM 标准瓦片服务作为批量图源的请求继续拦截。[OSMF 官方瓦片政策](https://operations.osmfoundation.org/policies/tiles/)明确区分正常浏览和批量抓取。
- 规划和估算可以自动进行；启动下载、改变持久化图源/设置、覆盖输出文件和删除成果需与具体参数绑定的可见确认。暂停和取消由用户或获得本次明确授权的任务操作触发。
- 任务失败、部分成功和真正完成必须由引擎与 manifest 判定。不得用模型文本替代文件检查；断点恢复不得把失败产物标成已完成。
- GeoD 托管模型显示剩余额度和本次实际用量；用量扣减、失败回退与充值记录由 GeoD 账号服务核算。瓦片费用及来源方配额另行提示，不能包装成 GeoD 模型额度。
- 账号可用于登录与图源同步。**是否把“未登录最高 5 级”扩展到这个新桌面产品仍需产品决策**；现行用户授权只覆盖 CLI、MCP、浏览器入口，不能静默限制现有桌面版。
- 外部 Agent 接入可复用同一个工具合同，通过本地 MCP 暴露有界能力；其进度由 GeoD Agent 桌面任务中心显示。远程 Web MCP 仍需区分服务器执行与用户电脑执行，不能仅改入口 URL 就宣称算力转移。

## 9. 能力发布顺序与验收门槛

### 阶段 A：真实影像闭环

交付独立可安装桌面程序，支持 GeoD 账号与托管模型、用户授权图源、对话描述区域与导入边界文件、估算、审批、下载、拼接、裁剪、GeoTIFF/离线成果、进度/取消/恢复、manifest/预览/质量。至少用一个合法且允许批量下载的真实图源完成完整端到端验证；示例概览源不能代替高分辨率验证。

### 阶段 B：现有 GeoD 数据任务适配

按各自的确定性任务合同接入 DEM、OSM 矢量、Wayback、3D Tiles 等。每一种都要有真实输入、失败样例、输出检查和可说明的限制；不能因为旧桌面有按钮，就自动向 Agent 暴露同名工具。

### 阶段 C：任务复用与外部生态

任务模板、批量队列、会话引用已有成果、本地 MCP 与 Skill、跨设备同步非敏感任务元数据。远程下发本地任务须单独设计设备在线状态和本机审批，不能让登录态直接成为远程下载执行权。

首个公开安装包的放行条件：

1. 干净 Windows x64 环境能安装、登录并完成一条真实影像任务；不要求用户安装 Node、GDAL 或手动配置 CLI。
2. 模型必须完成 `tool_call → tool_result → 继续计划/最终答复`，工具失败时解释可操作原因，不编造成果。
3. GeoD 账号的托管模型请求经过鉴权、限额和持久化用量账本；上游密钥不出服务端，断流/重试不重复扣减，账单可与上游用量对账。
4. 地图显示的边界与导出影像真实足迹一致；裁剪、坐标系、缺失瓦片、署名、manifest 和 SHA-256 都经过自动及人工抽检。
5. 相同计划的重复模型调用不产生第二个下载任务；暂停、取消、应用重启后的恢复均可验证。
6. 代理、无权限/超等级、磁盘不足、图源 403/429、断网、坏瓦片、部分瓦片缺失都有明确状态和恢复动作。
7. 抓包确认影像瓦片及拼接数据没有经过 GeoD 服务器；模型请求、用户授权和账号图源的敏感字段有脱敏审查。
8. 旧 GeoD 桌面版继续正常工作；新 Agent 安装和升级不删除旧版用户数据。独立安装包、版本号、更新及回滚通道均明确。
